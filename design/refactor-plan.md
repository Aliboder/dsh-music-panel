# 音乐面板重构方案（0.10.x）

> 目标：推翻现有拼接式界面，按成熟播放器的层级模型重建；先原型、后实现，逐步替换而非一次性重写。

## 0. 现状问题（为什么重构）

- 视图状态与布局耦合：`view / source / onlineMode / onlineCurrentPlaylist / npOpen / queueOpen …` 分散在同一个巨型组件里，任何改动都会牵连其他视图。
- 定位按钮、歌单横条、右键菜单、播放页都是"补丁式"叠加，层叠关系反复出错（按钮压底栏、浮层被播放页遮挡、歌单打开位置不对）。
- 离线/在线两套列表渲染逻辑重复，样式类前缀与结构不一致，视觉不统一。
- 缓存/歌词/翻译等状态没有统一来源，重复请求与竞态难以避免。

## 1. 参考规范（已调研）

成熟播放器（Apple Music / Spotify / YesPlayMusic / YouTube Music）的共同层级：

```text
App 外壳
└─ 面板（固定高度，唯一滚动）
   ├─ L1 顶栏（品牌/来源切换 + 全局操作）        —— 不滚动
   ├─ L1 内容区（单一滚动容器）                  —— 唯一滚动条
   │   ├─ 上下文头（标题 + 计数 + 操作）
   │   ├─ 选择器（Tab 条 / 歌单横条 / 过滤 chips）
   │   └─ 列表（虚拟化，行组件统一）
   ├─ L1 底栏（播放条：封面/信息/进度/控制/收藏） —— 常驻
   └─ L2 浮层（播放页 / 队列 / 右键菜单 / 设置抽屉 / 登录）
```

关键原则（YesPlayMusic 与 Apple Music 一致的做法）：

1. **唯一滚动区**：面板内只有内容区滚动，顶栏/底栏固定；避免嵌套滚动导致定位与滚动失效。
2. **内容区即"tab 容器"**：切换来源/歌单只替换内容区，不新增页面、不出现"返回上一页"。
3. **浮层只做遮挡**：播放页、队列、设置都是浮层，关闭后回到原滚动位置。
4. **行是唯一交互单元**：单击播放、右键菜单、悬浮显示播放键；不在行里塞按钮堆。
5. **状态分层**：持久化状态（tab/来源/音量）与瞬时状态（浮层/拖动/加载）分开。

## 2. 目标信息架构

```text
面板
├─ 顶栏
│   ├─ 品牌「音乐」
│   ├─ 来源 Tab：本地音乐 | 网易云 | QQ 音乐 | 酷狗
│   └─ 右侧：刷新 / 设置
├─ 内容区（唯一滚动）
│   ├─ 本地模式
│   │   ├─ 子导航：歌曲 | 专辑 | 歌手 | 收藏 | 统计 | 歌单
│   │   ├─ 工具行：搜索本地 / 排序 / 批量
│   │   └─ 列表 / 网格（统一行组件）
│   └─ 在线模式
│       ├─ 搜索行（输入 + 搜索）
│       ├─ 歌单横条（「最近播放」+ 我的歌单卡片，即 Tab 栏）
│       └─ 红框内容区（随横条选择切换）
│           ├─ 最近播放（历史列表，右键移除 / 清除不可播 / 定位）
│           └─ 歌单 X（该歌单曲目）
├─ 底栏播放条（常驻）
│   ├─ 封面 + 标题（缓存图标）+ 艺人
│   ├─ 进度条 + 时间（可拖动）
│   ├─ 随机 / 上一首 / 播放暂停 / 下一首 / 队列
│   └─ 收藏 / 打开播放页
└─ 浮层（按需）
    ├─ 播放页（全屏）：封面盘 + 歌词（含翻译）+ 进度 + 控制
    ├─ 队列浮层：当前播放 + 队列行 + 定位按钮
    ├─ 右键菜单：从最近播放移除 / 收藏 / 添加到歌单
    ├─ 设置抽屉：外观 / 歌词 / 音乐库 / 播放 / 在线
    └─ 登录二维码
```

### 在线区的关键交互（本次澄清）

- 歌单横条是**常驻 Tab 栏**，不会因为点击歌单而消失。
- 点击歌单卡片 → **只替换红框区域**：标题从「最近播放」变为歌单名，列表变为该歌单曲目；卡片高亮。
- 「最近播放」是横条第一个条目，点击回到历史列表。
- 不进入二级页面、不出现"返回上一页"按钮。

## 4. 状态模型

```text
持久化（localStorage / Host settings）
  ui.source      'local' | 'netease' | 'qq' | 'kugou'
  ui.view        本地子视图
  ui.onlineTab   'recent' | playlistId
  ui.volume      0..1
  prefs.*        歌词/翻译/缓存等

瞬时（组件内）
  player:   queue / index / playing / time / duration / buffered / error
  online:   query / results / loading / error / playlists / cached / progress
  overlay:  npOpen / queueOpen / context / settingsOpen / login
```

规则：

- **切换来源只重置在线 Tab 与结果，不破坏播放队列**。
- 歌单切换只改 `ui.onlineTab`，内容区由它派生，绝不写"页面前进栈"。
- 浮层关闭不改变内容区滚动位置（记住 scrollTop）。

## 6. 实施计划（分阶段替换，不中断使用）

**阶段 0｜冻结与准备**
- 新建 `lib/ui/` 目录（纯渲染函数），原型与截图入库 `design/`。
- 建立旧界面回归清单（见 §8）。

**阶段 1｜骨架**
- 引入 `PanelShell` + `ContentArea` + `PlayerBar` 三个容器，旧视图先塞进 `ContentArea`，样式不动。
- 验证：面板不滚动、只有内容区滚动；底栏常驻。

**阶段 2｜本地视图**
- 用 `TrackList`/`TrackRow` 重写本地歌曲/专辑/歌手/收藏/统计/歌单。
- 统一右键菜单（收藏/添加到歌单）。

**阶段 3｜在线视图**
- `OnlineView`：搜索行 + `PlaylistStrip` + 红框 `TrackList`。
- 最近播放：定位/清除不可播/右键移除；歌单切换只替换红框。
- 缓存图标、数量徽标接入。

**阶段 4｜播放与浮层**
- `NowPlaying`（歌词含翻译）、`QueueOverlay`、`SettingsDrawer`、`LoginDialog` 独立文件。
- 所有浮层用统一 `Overlay` 基础组件（遮罩 + 关闭 + 焦点）。

**阶段 5｜清理**
- 删除旧 `view === ...` 巨型三元渲染、废弃 CSS、未使用的 state/effect。
- 统一 i18n 文案 key 命名（`music.*`）。

**阶段 6｜回归**
- 跑全部测试 + SSR 6 注册 + 手动验收清单。

## 8. 验收清单

- [ ] 面板内只有内容区一个滚动条；顶栏/底栏固定。
- [ ] 切换来源不丢播放队列与进度。
- [ ] 歌单横条常驻；点击歌单只替换红框内容，卡片高亮，「最近播放」可切回。
- [ ] 定位按钮全局唯一，位于底栏上方；跨来源/歌单能跳到正在播放的列表并滚动到该行。
- [ ] 右键历史行出现菜单，移除后持久化。
- [ ] 播放页打开/关闭不改变列表滚动位置。
- [ ] 队列浮层不被播放页遮挡；播放页内队列入口可用。
- [ ] 缓存图标/进度、歌词翻译、VIP 徽标在在线行正确显示。
- [ ] 深色/浅色主题均用 token，无写死颜色。
- [ ] 全部测试通过，SSR 注册数不变。
