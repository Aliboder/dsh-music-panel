feat(ui): open a Navidrome connection dialog from the top-bar chip

The chip said 设置 and jumped to the settings sheet, which meant the user had
to find the right tab. It now says 连接 and opens a dedicated dialog.

NavidromeDialog (src/ui/19-navidrome-dialog.js) is a real component, not a
render helper, so its useState calls are safe under the Rules of Hooks
(test/panel.hooks.test.mjs still passes). It holds:

  - server URL   (validated as http(s) before submitting)
  - username
  - password
  - cancel / save footer, Enter submits and Escape closes

Saving posts to the existing /online/navidrome/login, which trades the
password for a salted token; the component clears its copy as soon as the
request settles, so the secret never lingers in UI state. On success it
reloads the provider summary, shows the server version, and closes after a
short delay so the confirmation is readable. Failures stay inline instead of
closing the dialog.

The chip now calls pushLayer('navidrome'); openNavidromeSettings() and the
props.tab support on SettingsSheet are removed since nothing uses them.

Strings: online.navidromeTitle / Save / NeedUser / NeedPassword in zh + en;
online.navidromeSetup dropped.

Verified: panel.render.test.mjs mounts the navidrome layer and asserts the
dialog renders all three labelled fields and the save button. npm test passes
(21 files), npm run check passes, client.js rebuilt at 42 fragments.
