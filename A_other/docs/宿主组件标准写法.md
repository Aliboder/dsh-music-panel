# DSH 官方组件标准写法（可移植参考）

> 来源：`dsh-music-panel` 的适配层（`src/client/components/ui/primitives.js`）与组件测试页（`src/client/components/ui/component-gallery.js`）。
> 已对照 DSH 0.2.2-rc.5 的宿主产物逐项核对，核对记录见 [宿主原语对照](../design/references/宿主原语对照-0.2.2-rc.5.md)。
> 目标插件：任何 DSH Client 插件；复制本文件的代码时，把 `mp-` 前缀换成自己的前缀即可。

## 0. 为什么要有这份文档

DSH 的控件（Button / Switch / Input / SegmentedControl / SegmentedTabs / Pill / Tag / Modal / Menu …）是宿主渲染的，插件在浏览器里通过 `require('@deepseek-ai/dsh-client-ui-primitives')` 拿到它们。这样做的好处是外观、键盘行为、主题全部与 DSH 本体一致；坏处是：

- 插件拿不到宿主的 CSS module，只能通过 **同一组 token + 同一组 props** 复刻；
- 宿主并非在所有版本/环境下都提供这套包，需要 **fallback**；
- 一旦某一侧走样，界面就会出现「差一点」的错觉，而且很难定位。

本仓的解法：

```text
host-ui.js        只在一个地方 require 宿主包，导出 hostComponent(name) / hostKitState()
primitives.js     每个控件一个适配层（Button / Switch / KitInput / …），宿主优先，fallback 同 props 同 DOM
component-gallery 组件测试页，每个用例 = 适配层名 + 实际控件 + 可复制的标准调用
theme.js          fallback 的 CSS，全部用 token，并与宿主 CSS 的几何逐项对齐
```

规则一句话：**测试页长什么样，业务里就只能长什么样；测试页没有的控件，不许上界面。**

---

## 1. 新插件的最小文件结构

```text
src/client/app/host-ui.js                       宿主组件加载器（唯一的 require 入口）
src/client/components/ui/primitives.js          适配层（本文件第 4 节）
src/client/components/ui/component-gallery.js   组件测试页（第 5 节）
src/client/styles/theme.js                      fallback CSS 与 token 固定（第 6 节）
```

客户端片段没有 `import`，按 `manifest.json` 顺序拼进同一个函数作用域。所以：

- 适配层里的函数名要唯一（不要和业务里的本地组件重名，尤其 `mpSmallButton` / `mpSegment` 这类）；
- CSS 用 `.mp-` 前缀隔离；
- 测试页依赖 `t()`、`cx()`、`icon()`、`h()` 这些全局辅助函数，移植时一并带上。

---

## 2. 宿主组件加载器（host-ui.js）

完整代码就这一个文件，保持短小：

```js
var hostUi = null
try {
  hostUi = require('@deepseek-ai/dsh-client-ui-primitives')
} catch (error) {
  hostUi = null
}

function hostComponent(name) {
  if (!hostUi) return null
  var value = hostUi[name]
  if (typeof value === 'function') return value
  if (value && typeof value === 'object' && value.$$typeof) return value
  return null
}

/** 面板真正会渲染的名字；关于页按它描述能力，不要按包名描述。 */
var HOST_KIT_COMPONENTS = [
  'Button', 'Switch', 'Modal', 'Input', 'Checkbox',
  'SegmentedControl', 'SegmentedTabs', 'Tag', 'StateDot',
  'Tooltip', 'Pill', 'Menu',
]

/** native = 全部能解析；partial = 包在但缺件；fallback = 包不可用。 */
function hostKitState() {
  if (!hostUi) return { state: 'fallback', missing: HOST_KIT_COMPONENTS.slice() }
  var missing = HOST_KIT_COMPONENTS.filter(function (name) {
    return hostComponent(name) === null
  })
  return { state: missing.length === 0 ? 'native' : 'partial', missing: missing }
}
```

注意：

- **不要**在业务代码里直接 `require` 宿主包；只有这个文件可以。这样升级/降级只改一处。
- 宿主图标也是原语包的一部分（`IconSearchOutlineRegular` 等）。用一个 `HOST_ICON_MAP` 把本地图标名映射到宿主图标组件，未命中的继续用本地 SVG。

---

## 3. 适配层原则

1. **宿主优先**：`hostComponent(name) !== null` 时渲染宿主组件，否则渲染本地等价物。
2. **两套路径同一组 props**：调用方永远只写一种调用；适配层负责把 `value/onChange` 等语义翻译成宿主期望的签名。
3. **DOM 语义一致**：`role`、`aria-*`、键盘行为、焦点样式两边都要有；fallback 不是「看起来像」就行。
4. **几何一致**：高度、圆角、内衬、字号、指示块动画都按宿主 CSS 抄（第 4 节每个控件末尾给了值）。
5. **fallback 只用 token**：颜色一律 `var(--dsw-alias-*)`，禁止写死十六进制；深色岛例外见第 6 节。
6. **onChange 语义由适配层统一**：`Switch/Checkbox` 收 boolean，`Input` 收 `(value, event)`，`Segmented*` 收 value 字符串，`Menu` 收 id。

---

## 4. 逐组件标准写法

每个控件给出：宿主签名（0.2.2-rc.5 实测）→ 适配层代码 → 业务里的标准调用 → fallback CSS 关键值。

### 4.1 Button

宿主签名：

```js
function Button({ variant = 'ghost', size = 'md', icon, className, children, ...rest })
// <button> 上展开 rest；icon 是 React 节点；variant: primary | ghost | outline | toolbar
```

适配层：

```js
function Button(props) {
  var variant = props.variant === 'primary'
    ? 'primary'
    : props.variant === 'ghost'
      ? 'ghost'
      : props.variant === 'toolbar'
        ? 'toolbar'
        : 'outline'
  var size = props.size === 'md' ? 'md' : 'sm'
  var HostButton = hostComponent('Button')
  if (HostButton !== null) {
    return h(HostButton, {
      variant: variant,
      size: size,
      icon: props.icon ? icon(props.icon, 16) : undefined,
      className: props.className,
      disabled: props.disabled === true,
      onClick: props.onClick,
      title: props.title,
    }, props.children)
  }
  return h('button', {
    type: 'button',
    className: cx('mp-btn', 'is-' + variant, size === 'md' && 'is-md', props.className),
    disabled: props.disabled === true,
    onClick: props.onClick,
    title: props.title,
  }, props.icon ? icon(props.icon, 14) : null, props.children)
}
```

标准调用：

```js
h(Button, { variant: 'primary' }, label)
h(Button, { variant: 'outline' }, label)
h(Button, { variant: 'ghost', icon: 'plus' }, label)
h(Button, { size: 'md' }, label)
h(Button, { disabled: true }, label)
```

fallback CSS（与宿主一致）：

```css
.mp-btn{height:28px;padding:0 10px;border-radius:var(--dsw-radius-sm,8px);
  font-size:12px;line-height:18px;gap:4px}
.mp-btn.is-md{height:36px;padding:0 14px;border-radius:var(--dsw-radius-md,12px);
  font-size:14px;line-height:22px}
.mp-btn.is-outline{box-shadow:inset 0 0 0 .5px var(--dsw-alias-border-l3)}
.mp-btn.is-primary{background:var(--dsw-alias-button-primary-fill);color:var(--dsw-alias-label-primary-foreground)}
.mp-btn:disabled{opacity:.4;cursor:not-allowed}
```

注意：宿主自身默认 `variant='ghost'`，本适配层默认 `outline`（显式传给宿主），两条路径因此一致。

### 4.2 IconButton（本地组合）

宿主没有 `IconButton` 导出。官方组合是 **Button/Tooltip + 图标**；本仓做的是：

```js
function IconButton(props) {
  var HostTooltip = hostComponent('Tooltip')
  var size = Number(props.size) || 16
  var button = h('button', {
    type: 'button',
    className: cx('mp-iconbtn', props.active === true && 'is-on', props.className),
    'aria-label': props.title || '',
    disabled: props.disabled === true,
    onClick: props.onClick,
  }, icon(props.icon, size))
  if (HostTooltip !== null && props.title) {
    return h(HostTooltip, { label: props.title, side: 'bottom', delayMs: 400 }, button)
  }
  return button
}
```

标准调用：

```js
h(IconButton, { icon: 'chevronLeft', title: label, onClick })
h(IconButton, { icon: 'play', title: label, active: true })
```

### 4.3 Switch

宿主签名：

```js
function Switch({ checked, onChange, label, disabled = false, title, className })
// <button role="switch" aria-checked aria-label>；onChange 收 boolean（取反后的值）
```

适配层：

```js
function Switch(props) {
  var HostSwitch = hostComponent('Switch')
  if (HostSwitch !== null) {
    return h(HostSwitch, {
      checked: props.value === true,
      onChange: function (next) {
        if (typeof props.onChange === 'function') props.onChange(next === true)
      },
      label: props.label || props.title || '',
      title: props.title,
      disabled: props.disabled === true,
      className: props.className,
    })
  }
  return h('button', {
    type: 'button', role: 'switch',
    'aria-checked': props.value === true ? 'true' : 'false',
    'aria-label': props.label || '',
    className: cx('mp-switch', props.value === true && 'is-on', props.className),
    disabled: props.disabled === true,
    onClick: function () { if (typeof props.onChange === 'function') props.onChange(!props.value) },
  }, h('i', null))
}
```

fallback CSS（宿主 36×20、2px 内衬、16px 滑块）：

```css
.mp-switch{width:36px;height:20px;padding:2px;border:0;border-radius:999px;

.mp-switch i{display:block;width:16px;height:16px;border-radius:50%;
```

### 4.4 Input（KitInput）

宿主签名：

```js
const Input = forwardRef(function ({ icon, className, ...inputProps }, ref) {
  // <span class=wrap>[icon]<input {...inputProps}/></span>
})
// onChange 是原生事件；value/type/placeholder/disabled/readOnly 都展开到 <input>
```

适配层：

```js
function KitInput(props) {
  var value = props.value === null || props.value === undefined ? '' : String(props.value)
  var label = props.label || props.placeholder || ''
  function change(event) {
    if (typeof props.onChange === 'function') props.onChange(event.target.value, event)
  }
  var HostInput = hostComponent('Input')
  if (HostInput !== null) {
    return h(HostInput, {
      value: value,
      type: props.type || 'text',
      placeholder: props.placeholder || '',
      icon: props.icon ? icon(props.icon, 16) : undefined,
      disabled: props.disabled === true,
      readOnly: props.readOnly === true,
      'aria-label': label,
      onChange: change,
      onKeyDown: props.onKeyDown,
      onBlur: props.onBlur,
      className: props.className,
    })
  }
  return h('span', { className: cx('mp-kit-input-wrap', props.className) },
    props.icon ? icon(props.icon, 15) : null,
    h('input', {
      className: 'mp-kit-input',
      type: props.type || 'text',
      value: value,
      placeholder: props.placeholder || '',
      disabled: props.disabled === true,
      readOnly: props.readOnly === true,
      'aria-label': label,
      onChange: change,
      onKeyDown: props.onKeyDown,
      onBlur: props.onBlur,
    }))
}
```

标准调用：`h(KitInput, { value, placeholder, icon: 'search', label, onChange })`

fallback CSS：

```css
.mp-kit-input-wrap{display:inline-flex;align-items:center;gap:6px;height:32px;padding:0 8px;
  border:.5px solid var(--dsw-alias-border-l4);border-radius:var(--dsw-radius-md);
  background:var(--dsw-alias-bg-layer-1)}
.mp-kit-input-wrap:focus-within{border-color:var(--dsw-alias-state-business-primary)}
```

### 4.5 Checkbox（KitCheckbox）

```js
function Checkbox({ checked, onChange, label, disabled = false, title, className, modalAutofocus = false })
```

```js
function KitCheckbox(props) {
  var HostCheckbox = hostComponent('Checkbox')
  if (HostCheckbox !== null) {
    return h(HostCheckbox, {
      checked: props.checked === true,
      onChange: function (next) {
        if (typeof props.onChange === 'function') props.onChange(next === true)
```

### 4.6 SegmentedControl（KitSegmented）

宿主签名：

```js
function SegmentedControl({ id, value, options, onChange, label, disabled = false, className })
// options: [{ value, label, title, disabled }]；id 会派生出 `${id}-${value}` 与 `${id}-${value}-panel`
// value 用 === 比较：调用方务必统一成字符串
```

适配层要点：

```js
// 每个实例一个 id：固定默认 id 会让同页多个分段产生重复 DOM id / aria-controls
var idRef = useRef(null)
if (idRef.current === null) {
  MP_SEGMENT_SEQ += 1
  idRef.current = 'mp-seg-' + String(MP_SEGMENT_SEQ)
}
var id = props.id || idRef.current
```

宿主分支：

```js
return h(HostSegmented, {
  id: id,
  value: value,
  options: options.map(function (option) {
    return { value: String(option.value), label: option.label,
      disabled: option.disabled === true, title: option.title }
  }),
  onChange: function (next) { if (typeof props.onChange === 'function') props.onChange(next) },
  label: label,
  disabled: props.disabled === true,
  className: props.className,
})
```

fallback 分支（结构必须与宿主相同：一个绝对定位的指示块 + 等宽 tab）：

```js
return h('div', {
```

适配层：

```js
function KitPill(props) {
  var HostPill = hostComponent('Pill')
  var content = [props.icon ? icon(props.icon, 13) : null,
    h('span', { key: 'label' }, props.children)]
  if (HostPill !== null) {
    return h(HostPill, { active: props.active === true, className: props.className,
      title: props.title, onClick: props.onClick }, content)
```

### 4.9 Modal（KitModal）

宿主签名：

```js
function Modal({ open, onClose, title, closeLabel, description, children, footer,
  className, contentClassName, headless = false, backdropBlur = true, tone })
// 自己处理 portal、焦点陷阱、Escape；open 由调用方持有
```

适配层要点：调用方按需挂载（`open` 恒为 true），宿主负责其余；fallback 需要自己维护 Escape 栈：

```js
if (HostModal !== null) {
  return h(HostModal, {
    open: true,
    onClose: props.onClose,
    title: props.title || '',
    closeLabel: t('v2.close'),
    children: h('div', { className: 'mp-kit-body' }, props.children),
    footer: props.footer,
    className: cx('mp-kit-modal', props.small === true && 'is-sm', props.className),
    contentClassName: 'mp-kit-content',
  })
}
```

standalone 的 headless 分支传 `{ open: true, onClose, headless: true, children }`。

### 4.10 Menu / Select / HeadMenu

宿主签名（摘要）：

```js
function Menu({ open, anchor, items, selectedId, onSelect, onClose, side = 'bottom',
  align = 'start', portal = false, compact = false, ... })
// anchor 是 React 元素（宿主把它渲染进自己的根 span，并用 CSS anchor 定位）
// items: [{ id, label, icon, disabled, danger, shortcut, submenu, type: 'separator' }]
// onSelect(id)；selectedId 画勾
```

下拉选择的适配层：

```js
var trigger = h('button', {
  type: 'button',
  className: cx('mp-select', open && 'is-open'),
  'aria-label': props.label || '',
  'aria-haspopup': 'listbox',
  'aria-expanded': open ? 'true' : 'false',
  disabled: props.disabled === true,
  onClick: function () { setOpen(!open) },
}, h('span', { className: 'mp-select-label' }, current ? current.label : props.placeholder || ''),
  icon('chevronDown', 14))

if (HostMenu !== null) {
  return h(HostMenu, {
    open: open,
    anchor: trigger,
    items: options.map(function (option) {
      return { id: String(option.value), label: option.label, disabled: option.disabled === true }
    }),
    selectedId: value,
    onSelect: function (id) { setOpen(false); if (typeof props.onChange === 'function') props.onChange(id) },
    onClose: function () { setOpen(false) },
    side: 'bottom',
    align: 'start',
    portal: true,
    compact: true,
  })
}
```

顶栏菜单同理（`HeadMenu`）：`items` 里 separator 用 `{ type: 'separator', id }`，动作项带 `{ id, label, icon, disabled, danger }`，`selectedId` 取当前激活项。

### 4.11 Toast / 轻提示

宿主有 `Toast` **组件**（`{ text, icon, tone, anchor, holdMs, actions, onDone }`），但插件通常用**服务式**提示：

```js
function showToast(text) { /* 自己管队列、自动消失、aria-live */ }
```

两者不要混用：组件式 Toast 适合「挂在某个锚点旁边的一条消息」，服务式适合「操作反馈」。本仓测试页用 `showToast`，并在说明里写明这是有意差异。

### 4.12 其余共用件

```js
h('input', { type: 'range', className: 'mp-range', min, max, value, onChange })
h(Spinner)
h(Empty, { icon, title, hint })
h(SetRow, { label, desc }, control)
```

`SetRow` 是设置行的统一骨架（label + 可选说明 + 右侧控件），不需要宿主组件：

```js
function SetRow(props) {
  return h('div', { className: 'mp-set-row' },
    h('div', { className: 'mp-set-label' }, props.label,
      props.desc ? h('span', { className: 'mp-set-desc' }, props.desc) : null),
    h('div', { className: 'mp-set-control' }, props.children))
}
```

## 5. 组件测试页（component-gallery.js）

测试页的每个用例 = **适配层名 + 实际控件 + 可复制的标准调用**。页面本身只做三件事：列出区块、渲染真实控件、把调用代码显示在下面。

### 5.1 用例骨架

```js
/** 一个参考用例：适配层名、实际控件、可复制的调用。 */
function GalleryCase(props) {
  return h('div', {
    className: cx('mp-gallery-case', props.wide === true && 'is-wide'),
    'data-adapter': props.adapter || undefined,
  },
    h('div', { className: 'mp-gallery-case-title' }, props.title,
      props.adapter ? h('span', { className: 'mp-gallery-adapter' }, props.adapter) : null),
    h('div', { className: 'mp-gallery-row' }, props.children),
    props.code ? h('pre', { className: 'mp-gallery-code' }, h('code', null, props.code)) : null,
  )
}
```

### 5.2 一个完整用例（开关）

```js
var switchPair = useState(true)
var switchOn = switchPair[0]
var setSwitchOn = switchPair[1]

h(GalleryCase, {
  title: t('gallery.caseSwitch'),
  adapter: 'Switch',
  code: "h(Switch, { value, label, onChange })",
}, h(Switch, { value: switchOn, label: t('gallery.caseSwitch'), onChange: setSwitchOn }),
   h(Switch, { value: !switchOn, label: t('gallery.caseSwitch'), onChange: setSwitchOn }),
   h(Switch, { value: false, label: t('gallery.caseSwitch'), disabled: true }))
```

代码字符串里用 `label` / `value` / `onChange` 这类**占位符**，不要写 `t('gallery.xxx')`，否则从测试页复制到业务还得再改一遍文案键。

### 5.3 页面框架

```js
var GALLERY_SECTIONS = [
  { key: 'buttons', labelKey: 'gallery.secButtons' },
  { key: 'form', labelKey: 'gallery.secForm' },
  { key: 'navigation', labelKey: 'gallery.secNav' },
  { key: 'overlays', labelKey: 'gallery.secOverlays' },
  { key: 'states', labelKey: 'gallery.secStates' },
]

var hostKit = hostComponent('Button') !== null ? 'native' : 'fallback'

return h('div', { className: 'mp-gallery' },
  h('div', { className: 'mp-gallery-head' },
    h(IconButton, { icon: 'chevronLeft', title: t('gallery.back'), onClick: props.onClose }),
    h('div', { className: 'mp-gallery-title' }, t('gallery.title')),
    h('span', { className: 'mp-gallery-hint' }, t('gallery.usageHint')),
    h('span', { className: 'mp-gallery-hint' }, t('gallery.hostKit') + ': ' +
      (hostKit === 'native' ? t('gallery.native') : t('gallery.fallback')))),
  h('div', { className: 'mp-gallery-body' },
    sectionNav,
    h('div', { className: 'mp-gallery-main', role: 'tabpanel' }, sectionBody())))
```

`usageHint` 写死一句：「用例里的 adapter + 代码就是规范的标准写法，可整段照抄」——让后来的人（和 AI）知道该抄哪里。

### 5.4 新增一个用例的检查清单

1. `adapter`：写适配层函数名（`Button` / `KitSegmented` / `Switch` / …），不要写宿主导出名或 CSS 类名；
2. `code`：真实可运行的调用，props 用占位符，单行优先；
3. 实际控件：至少覆盖默认态 + 一个非默认态（禁用/选中/小尺寸）；
4. 文案：zh 与 en 各一条 `gallery.caseXxx`；
5. 如果这个控件有 fallback，把宿主组件临时禁用（或改 `hostComponent` 返回 null）看一遍；
6. 最后跑一遍页面：native / fallback、浅色 / 深色、窄宽度。

## 6. Token、几何与深色岛

### 6.1 几何速查

| 用途 | 值 |
|---|---|
| 小圆角 | `--dsw-radius-sm` 8px |
| 中圆角 | `--dsw-radius-md` 12px |
| 大圆角 | `--dsw-radius-lg` 16px |
| 卡片圆角 | `--dsw-radius-xl` 20px |
| 发丝线 | `.5px`（不要 1px） |
| 按钮 sm / md | 28px / 36px |
| 输入框 | 32px，内衬 0 8px |
| 分段控件 tab | 28px |
| 分段页签 tab | 34px（sm 30px） |
| 开关 | 36×20，滑块 16，内衬 2 |
| 焦点环 | `outline: var(--dsw-focus-ring-width) solid var(--dsw-focus-ring-color)`，offset 2px（分段 offset -2px） |

### 6.2 交互约定

- hover 一律包在 `@media (hover: hover)` 里，触摸设备不要粘住；
- disabled：`opacity:.4`（开关 `.5`）+ `cursor:not-allowed`；
- 过渡：颜色 `.12s`、位移 `.16s ~ .18s`；
- 键盘：`role=tab` 需要方向键 + Home/End；宿主已经做了，fallback 要补。

### 6.3 深色岛（深色面板里的浅色主题）

若你的面板在浅色主题下仍然是深色（本仓的播放卡片就是），宿主控件读到的 token 会变成浅色系，必须在岛根**重新钉一遍**，而且钉成深色主题的**同一组静态来源**，不要手写近似色：

```css
.mp-card{
  --dsw-alias-label-primary:var(--dsw-static-neutral-bluish-50);
  --dsw-alias-label-secondary:var(--dsw-static-neutral-bluish-300);
  --dsw-alias-label-tertiary:var(--dsw-static-neutral-bluish-400);
  --dsw-alias-label-primary-foreground:var(--dsw-static-neutral-bluish-1000);
  --dsw-alias-bg-module-platform:var(--dsw-static-neutral-bluish-800);
  --dsw-alias-brand-primary:var(--dsw-static-neutral-bluish-50);
  --dsw-alias-switch-thumb:var(--dsw-static-neutral-bluish-400);
  --dsw-alias-border-l3:rgba(255,255,255,.16);
}
```

规则：深色岛里**没有钉 token 的宿主控件不要用**；开关、分段、输入框都是 token 驱动，漏一个就会在浅色主题下变白。

## 8. DSH 升级后如何复核

1. 解析 `app.asar`：前 16 字节后是 JSON 头，`offset 12` 是 JSON 字节长度，数据起点 `16 + jsonLen`；
2. 取 `dsh/node_modules/@deepseek-ai/dsh-web-frontend/dist/assets/index-*.js`；
3. 搜 `const DK=Object.freeze`，得到原语导出表；按名字找到组件函数，读 props 解构；
4. 取同目录 `index-*.css`，搜 `_switch_` / `_control_` / `_tabs_` / `_button_` / `_pill_`，逐项比对第 4 节的 fallback 值；
5. 有变化时：先改测试页与 fallback，再改业务；更新 [宿主原语对照](../design/references/宿主原语对照-0.2.2-rc.5.md) 的版本号与结论。
