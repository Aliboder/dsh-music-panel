## 1. 背景不随音乐扭曲、暂停后还在匀速动

- **现象**：隐现（流体/混合）只有缓慢流动，没有鼓点形变；暂停后背景仍按原速动。
- **原因**：Folia 跑 React **19**，函数组件把 `ref` 当普通 prop 透传；宿主固定 React **18.3.1**，
  `memo(function …)` 不转发 `ref`。`paperShaderMount` 恒为 `null`，latent 里逐帧的
  `setSpeed` / `u_distortion` / `u_swirl` / `u_pxSize` 全被 `if (currentMeshMount)` 跳过。
- **处理**：vendored `src/render/folia/vendor/paper-shaders-react/dist/shaders/*.js` 的 7 个
  包装改为 `memo(forwardRef(function …))`，并把 `ref` 传给底层 `ShaderMount`；重建
  `backgrounds.bundle.js`。
- **防回归**：`test/folia-backgrounds.test.mjs` 断言 bundle 里存在
  `forwardRef(function MeshGradientImpl(` 等包装。

## 2. 改了背景源码，画面却没变

- **现象**：改了背景/样式源码并重启，画面还是旧的；`client.js --check` 却通过。
- **原因**：`backgrounds.bundle.js`、`styles.bundle.js`、`pendolo.bundle.js` 是独立产物，
  `node scripts/build-client.mjs --check` 只校验 `client.js` 的拼接，不会发现 bundle 过期。
- **处理**：改背景源码或 `vendor/paper-shaders*` 后，顺序固定为
  `node scripts/build-backgrounds.mjs` → `node scripts/build-client.mjs`。
  时计/样式同理：`build-pendolo.mjs` / `build-styles.mjs`。
- **防回归**：提交前看 `git status` 是否包含对应 `.bundle.js`；不要手改生成物。

## 3. bands 归一化成 0..1，背景完全静止

- **现象**：背景有轻微流动，但鼓点完全不起作用。
- **原因**：Folia 背景用 `useTransform(spring, [10, 200], [0.95, 1.45])`，输入必须保持 0–255；
  0..1 永远落在映射的第一档。
- **处理**：`process(v, boost) = (v / 255) ** boost * 255`，五条 band 与 `audioPower` 都输出 0–255
  （见 `src/render/styles/folia-audio.js`）。
- **防回归**：`test/folia-audio.test.mjs` 断言输出范围；不要在客户端再做一次 0..1 归一化。

## 4. 「鼓动很弱」不一定是带宽，可能是分析器 smoothing

- **现象**：低频段有值，但鼓点看起来总是被抹圆。
- **原因**：插件旧 analyser `smoothingTimeConstant = 0.82`，Folia 是 **0.6**；额外平滑把鼓点抹圆。
- **处理**：`src/50-player.js` 改为 0.6。插件自己的频谱条会做峰值归一化，不会因此变噪。
- **防回归**：改动音频分析器参数时，对比 `folia-audio.js` 的输出与 Folia 的上游值。

## 5. 莫奈底部频谱条比 Folia 钝

- **现象**：莫奈样式的底部频谱条只有几段高低，没有细密频谱。
- **原因**：没提供 `audioBands.spectrum`，`Monet AudioOverlay` 回退到五段 band 插值。
- **处理**：每帧 `new Uint8Array(wave)` 写入 `spectrum`。不要直接复用 analyser 的 buffer
  （下一帧会覆盖已经发给 MotionValue 的值）。
- **防回归**：`test/folia-audio.test.mjs` / 样式测试覆盖 spectrum 字段。

## 6. 暂停时背景仍缓慢变化

- **现象**：按暂停后背景还在很慢地动。
- **原因**：Folia 的隐现暂停时是 `base × 0.12`，**不是 0**，观感是「几乎停住」，不是完全冻结。
- **处理**：先确认第 1 条的 ref 是否生效；12% 慢速符合上游行为，不要当 bug 修。
- **防回归**：不要用「暂停时完全不动」做断言；断言的应该是 bands 停止更新。

## 7. 不是所有背景都吃音频

- **现象**：切到莫奈/漫游/空/嵌入后，鼓点没有反应，以为音频分析坏了。
- **原因**：只有 **隐现（latent）** 与 **通用（common，几何图形）** 吃音频。莫奈/漫游/空/嵌入
  在上游就是封面或时间驱动，静止是设计如此。
- **处理**：想测音频响应就用隐现（流体/混合）或通用；不要把其他背景的静止当 regression。
- **防回归**：文档和测试里写清「哪些背景吃音频」。

## 8. 看到的还是旧背景（模糊封面 + 斜线）

- **现象**：刷新/重启后播放页仍是旧 ambient 背景，和新代码不一致。
- **原因**：旧 ambient 背景的封面回响层（`.mp-np-bg` 的 `is-echo`）还在运行中的旧 client 里；
  新播放页不再渲染它。
- **处理**：重启 DSH 或刷新页面；确认 `client.js` 是新的（安装目录里的哈希/关键字符串）。
- **防回归**：改播放页背景后检查运行的 client，不要只看仓库文件。

## 9. 没歌词时页面中央一直有「暂无歌词」

- **现象**：纯音乐/无歌词时，播放页中央出现占位文案，挡住视觉器。
- **原因**：两处占位（`src/ui/04-now-playing.js`、`src/ui/04-player-page.js`）及对应 CSS 已移除。
- **处理**：`page.noLyrics` 的 i18n key 仍保留，暂未使用；不要再把占位加回来。
- **防回归**：无歌词时只让视觉器/空舞台处理，不渲染文案占位。

## 10. 浅色主题下播放器卡片白底白字（主题 / UI）

- **现象**：浅色主题打开播放页的播放器卡片，圆角块、胶囊、输入框、页签变成白底白字，
  文字几乎看不见；深色主题正常。
- **原因**：卡片背景固定为深色玻璃（`rgba(23,23,26,.95)`，属于深色岛），但内部控件读的是宿主
  token（`--dsw-alias-bg-layer-2` 等）；浅色主题把它们解析成近白表面/深色文字。
- **处理**：在 `.mp-card` 作用域把用到的 token 钉成深色值（与 `.mp-np` 的深色岛一致），
  新浮层照此办理；不要逐个子组件打补丁。
- **防回归**：`test/theme.test.mjs` 的 `.mp-card` 断言；浅色主题下专门看卡片和浮层。

## 11. 主题守卫有扫描盲区：新 UI 文件 + 内联圆角（构建 / 测试）

- **现象**：在 `20-player-sheet.js` / `25-look-picker.js` 里写了 `borderRadius: '10px'`、
  `fontSize: '11.5px'`，`npm test` 仍然通过。
- **原因**：`test/theme.test.mjs` 的字号检查只扫手写的 `uiFiles`（到 `16-header.js`）；
  圆角检查只扫 `90-theme.js` 的 CSS，内联 `borderRadius` 根本没查。
- **处理**：新增 `src/ui/*.js` 时把文件名加进 `uiFiles`；内联圆角也按 8/12/16/20 写。
  扩大守卫前先清旧违规（卡片里还有 10px / 11.5px 等历史值），不要一次性打开。
- **防回归**：新增 UI 文件的 review 清单包含「更新主题守卫的 `uiFiles`」；扩守卫时分批提交。

## 12. 只在 native 宿主组件下看，fallback 坏了（主题 / UI）

- **现象**：真实 DSH 里控件正常，测试/harness 或旧版 DSH 里控件缺失、错位、无法点击。
- **原因**：`hostUi` 加载失败时 `hostComponent` 返回 `null`，走本地 fallback；测试环境固定
  fallback，但本地只验证了 native。
- **处理**：native 和 fallback 都看一遍；看控制台 `host UI kit: native|fallback` 和设置页状态行；
  fallback 保持同 DOM/class/props，不另起一套外观。
- **防回归**：新增宿主组件必须同时有 fallback 与渲染测试（测试环境默认 fallback）。

## 13. 改了源码，已安装插件却没变（安装 / 调试）

- **现象**：重新 build-client、刷新页面，界面还是旧逻辑。
- **原因**：profile 里的插件可能是从 tarball / `file:` 安装的**副本**，不是工作区 link；
  工作区构建只改仓库的 `client.js`。即使是 link，Host 模块也要重启才会换新的模块代际。
- **处理**：开发期用 link 安装；交付前 `npm pack` 后重新安装。装完刷新客户端加载新
  `client.js`，完全重启 DSH 加载新 Host。
- **防回归**：安装后直接检查安装目录的 `client.js` 是否含新字符串/哈希，不要只看 lockfile。

## 14. `install_bundle` 被 `ERR_PNPM_EXOTIC_SUBDEP` 拦下（安装 / 发布）

- **现象**：在 profile 里安装/更新插件时报
  `Exotic dependency "kugoumusicapi" (resolved via url) is not allowed in subdependencies when blockExoticSubdeps is enabled`。
- **原因**：`package.json` 里 `kugoumusicapi` 是 GitHub tarball URL；DSH 的 pnpm 供应链策略
  默认禁止子依赖里的 exotic dependency。
- **处理**：本地临时用
  `pnpm add <tgz> --config.block-exotic-subdeps=false --ignore-scripts` 安装；
  发布前必须解决（换成 registry 包，或让安装器允许该依赖/改为可选依赖），不要把这个参数
  当正式安装方式。
- **防回归**：发布前在干净 profile 走一遍 `install_bundle`；CI 加打包安装冒烟。

## 15. 同版本 tarball 改了内容，`pnpm add` 不换已装文件（安装 / 调试）

- **现象**：重新 pack 覆盖同名 tarball，`pnpm add` 成功、lock 的 integrity 也变了，但
  `node_modules/dsh-music-panel` 里还是旧文件。
- **原因**：hoisted linker 认为该版本已安装，只补依赖；或 store 命中了旧内容。
- **处理**：删掉 `node_modules/dsh-music-panel` 后按 tarball 重新解压/安装，或升版本号；
  装完用关键字符串/哈希确认 `client.js` 是新的。
- **防回归**：安装后校验安装目录文件，不只看 lockfile 或命令退出码。

## 16. 删除 junction 安装时可能误删源码（安装 / 调试）

- **现象**：清理 `node_modules/dsh-music-panel` 时，把链接目标（工作区仓库）一起删了。
- **原因**：Windows junction 在某些递归删除/资源管理器操作里会被跟随。
- **处理**：先 `Get-Item` 确认 `LinkType=Junction`，用 `cmd /c rmdir "<path>"` 只删链接；
  删完确认目标仓库还在。
- **防回归**：删除前打印 link target；不要对不确定的路径直接 `Remove-Item -Recurse`。

## 17. 卸载/重装前没停插件，数据又回来了（安装 / 数据）

- **现象**：删了 `~/.dsh/music`，几秒后又出现 `playback.json` / `cache`；重启后旧队列还在。
- **原因**：插件仍在运行，播放/切歌会写回；关闭窗口时 client 的 `beforeunload` 还会
  `flushOnHide()` 保存当前队列。
- **处理**：先用 `plugin_manager` 停用插件，再删数据；重装后先刷新页面丢掉旧队列，再退出重启。
- **防回归**：卸载/重装按「停用 → 删数据 → 安装 → 刷新/重启」顺序，不要先删目录。

## 18. 渲染层 localStorage 不随卸载消失（安装 / 数据）

- **现象**：重装后仍记得歌词样式、主题、引导已读。
- **原因**：`music.prefs.v2`、`dsh-music.prefs`、`music.startupGuide.intro.v1` 在 DSH 渲染进程
  的 localStorage，不在 `~/.dsh/music`；普通卸载不会删（与宿主行为一致）。
- **处理**：需要真正首次体验时，在 DSH DevTools 里 removeItem 这几个 key 再 reload；
  不要以为删数据目录就能清掉界面偏好。
- **防回归**：文档写清「磁盘数据」和「渲染层偏好」的边界；不要承诺卸载=清空所有偏好。

## 19. `--st-raise` 不是 Folia 注入的变量（主题 / UI）

- **现象**：想用 `--st-raise` 调选中胶囊的抬升色，改了没反应。
- **原因**：仓库里没有任何 `--st-raise:` 定义；`var(--st-raise, rgba(255,255,255,.18))` 永远走
  fallback。
- **处理**：深色岛用白色 alpha，主题化用业务 token / `color-mix`；不要依赖未定义变量。
- **防回归**：review 时看到没有定义的 CSS 变量直接指出；`Select-String '--st-raise:'` 为空。

## 20. 手工 insert、bundle selection 与 `set_plugin` 覆盖是三套状态（安装）

- **现象**：插件能跑，但插件管理器显示「已停用」；或删了 `insert` 后重启状态又不对。
- **原因**：正常安装是「依赖 + `dsh.profile.bundles` 选中 → 包内 `cordis.patch.yml` 插入」；
  手工在 profile 的 `cordis.patch.yml` 写 `- insert: id: music` 会绕开管理器。`set_plugin`
  禁用又会在 patch 末尾追加 `- id: music` + `disabled: true`，是另一层覆盖。
- **处理**：按 `install_bundle` 的形态安装：依赖 + `dsh.profile.bundles`，不要手工 insert；
  清理时全文搜 `music`，同时处理 insert 和末尾 override。
- **防回归**：用 `plugin_manager list_bundles` 看 `enabled` / `rows`，再对 `list_plugins` 的
  `include:music` 状态；两边一致才算装好。

## 21. 生成物清单：`client.js --check` 只管拼接（构建）

- **现象**：改完源码，`build-client --check` 通过，但样式/歌词/背景还是旧的。
- **原因**：`client.js` 是 `src/**` 的 fragment 拼接产物；独立生成物还有
  `lyrics.bundle.js`、`styles.bundle.js`、`backgrounds.bundle.js`、`pendolo.bundle.js`、
  `folia-tailwind.js`、`vendor/*.bundle.js`、`lib/assets/icu-folia/*.json.gz`。
- **处理**：按 `AGENTS.md` 的命令先重建对应 bundle，再 `build-client`；`icu-folia` 需要
  `folia-major-main` 检出。不要直接改生成物。
- **防回归**：提交前 `git status` 应包含预期的生成文件；review 时检查「源码改了，bundle 有没有改」。

## 22. client.js 顶层声明重名 / `.bundle.js` 被重复扫描（构建）

- **现象**：构建后浏览器报 `Identifier '…' has already been declared`，或新 fragment 的函数被同名旧声明覆盖。
- **原因**：`client.js` 是 `src/**` 拼接的单个 IIFE，所有 fragment 共享作用域，顶层 `var/function/const` 必须唯一；`.bundle.js` 是独立产物，构建时跳过重复扫描，不受这条约束。
- **处理**：新增顶层名一律带 `mp` 前缀并先搜同名；改 `.bundle.js` 走对应 `build-*` 脚本，不要直接改 `client.js`。
- **防回归**：`node scripts/build-client.mjs --check` + `node --check client.js`；CI 跑全量测试。

## 23. 只改 `folia-tailwind.css`，线上仍是旧样式（构建）

- **现象**：改了 `src/render/folia/folia-tailwind.css`，刷新后样式没变。
- **原因**：Tailwind 有两份。`.css` 是生成结果，`client.js` 实际注入的是 `folia-tailwind.js`
  里的字符串；仓库目前没有专门生成这份 `.js` 的 build 脚本。
- **处理**：改 Tailwind 后同步把新 CSS 写进 `folia-tailwind.js`（保持现有字符串格式），
  或先补一个生成脚本；最后 `build-client`。不要只改 `.css` 当交付物。
- **防回归**：提交前确认 `.css` 和 `.js` 都变了，并抽查一个新增 utility 是否在 `.js` 里。

## 24. Folia 资源 404 / `import.meta.glob` 不存在（Folia）

- **现象**：样式里的图片、字体、背景 404；或代码用了 `import.meta.glob` 直接报错。
- **原因**：插件运行在浏览器 IIFE，不是 Vite 构建；资源 URL 必须相对 `document.baseURI` 解析为绝对地址，也没有 Vite 的静态分析 API。
- **处理**：用 `new URL(path, document.baseURI).href`；资源走插件导出或 `/music/...` 路由；不要依赖 Vite 专有 API。
- **防回归**：在带子路径的部署下打开插件，确认资源请求 URL 正确。

## 25. 暂停判断信 snapshot，bands 继续写（播放 / 音频）

- **现象**：按暂停后背景/频谱仍在动，或恢复播放时状态错位。
- **原因**：player snapshot 可能滞后；真实 `<audio>` 的 `paused` / `ended` 才是权威状态。
- **处理**：暂停判断读 `<audio>` 的 `paused/ended`；暂停时停止写 bands（或写 0），恢复时重新启动。
- **防回归**：暂停/恢复测试断言 bands 停止/恢复；不要只断言 `snapshot.playing`。

## 26. `VisualizerShell` 没转发 ref，心象拿不到尺寸（Folia / UI）

- **现象**：心象样式的 `ResizeObserver` 尺寸为 0，画面不显示或错位。
- **原因**：`VisualizerShell` 必须 `forwardRef` 转发容器 ref；普通函数组件会丢掉 ref。
- **处理**：用 vendored 的 `forwardRef` 包装并转发到容器（与 paper-shaders 的 React 18 处理一致）。
- **防回归**：样式测试断言 ref 转发/容器有尺寸；新增 Folia 包装时先搜 `forwardRef`。

## 27. 移除功能后偏好没迁移（偏好 / 迁移）

- **现象**：老用户升级后样式空白或回退错误；旧 `classic` / `cappella` / `machi` 仍然生效。
- **原因**：已移除功能的偏好没有映射到当前默认样式，或者迁移只改内存没写回。
- **处理**：在 `src/30-prefs.js` 的迁移里把旧 id 映射到 `classic`；旧默认 `monet` 仅迁移一次，用户主动选择后写入 `lyricStyleChosen`，新增移除功能保持同样行为并一次性写回。
- **防回归**：注入旧偏好值跑迁移测试；不要只测全新用户。

## 28. 歌词 / icu-folia 生成物：不要手改（构建 / 歌词）

- **现象**：改了歌词解析或词典，线上没变；手改 `.json.gz` 后又无法复现。

## 34. 在线缓存按「播完」触发时，交叉淡化的那首永远不缓存（播放 / 缓存）

## 49. 交叉淡入淡出后所有歌词样式冻结在每句第一个字

- **现象**：播放一段时间、发生切歌淡入淡出后打开播放页，所有 Folia 歌词样式的逐字/逐词动画停在每句第一个字，行索引仍会跳下一句。
- **原因**：共享时钟用 `document.querySelector('audio.mp-audio-host')`，查到的是文档里的旧 A deck；active deck 已切到 B，旧 A 在 `finishCrossfade` 里被 `removeAttribute('src') + load()`，时间归 0。行索引来自 active deck，时钟却停在 0。
- **处理**：播放器暴露 `getPlaybackTime()` / `getActiveAudio()`；Folia 样式、Pendolo、音频带全部读 active deck。Folia 也是如此：共享 lyric clock 来自 active transport。
- **防回归**：player-folia-runtime 断言 `getActiveAudio()` 与 `getPlaybackTime()` 跟随挂载的 deck。

## 50. 逐词歌词和实际进度对不准

- **现象**：逐词扫色/高亮和实际进度有偏差，行切换时尤其明显；Folia 同一首歌、同一词源正常。
- **原因**：Folia 舞台的 currentTime 是约 60Hz 的 rAF 时钟，但当前行索引来自父层 usePlayerTime() 的 timeupdate（约 4Hz）。两个时钟在行边界最多错开约 250ms，逐词动画和行索引不同步。
- **处理**：在 FoliaStyleStage 内用同一 clock 逐帧计算 foliaLineIndex（与 Folia 的 findLatestActiveLineIndex 一致，行间间隙返回 -1），不再依赖父层 active。
- **防回归**：foliaLineIndex 覆盖行内、行间、renderEndTime 与最后一行；player 测试继续覆盖 active deck 时钟。

## 51. 歌词记录标记 wordLevel，payload 却只有 LRC

## 64. 网易云歌单只加载 1000 首

- **现象**：某些平台的歌单只显示固定数量：网易云 1000、波点 100、汽水 60、酷狗标准版 300、酷狗概念版 2000/4000。
- **原因**：Host 的 `playlistSongs` 只请求第一页，把单页 `limit/pagesize` 当成了总数。Folia 的 provider 接口是 `getPlaylistTracks(id, limit, offset)`，UI 按页继续请求。
- **处理**：网易云按 `trackCount` 以 500 首循环；波点按 100 首、汽水按 60 首并用 `hasMore`、酷狗标准版按 300 首、概念版按 100/200 首继续翻页，直到 total、hasMore 结束或短页。QQ 自建/喜欢已有分页，Navidrome/本地无固定上限。
- **防回归**：任何“全量列表”接口都要核对上游分页语义；单请求 `limit` 不能当作总数，必须用 `trackCount`/`hasMore`/短页终止。

## 65. 花火/绘光的歌词变成竖排

## 66. 智能平衡只有常量像 Folia

- **现象**：目标 -14 LUFS、+6 dB 等常量与 Folia 相同，但同一首歌的 dB 和播放中移动仍可能不同。
- **原因**：本地只实现了 file/played/tag/live/typical 五级来源；缺少 profile/head/platform，typical 不去重，实时 meter 用本地简化记录，文件缓存的是最终 gain，播放中也没有 blend hold。
- **处理**：生产规则直接使用 `MPAudio.chooseBalance` / `planBalanceMove` / `whyNotWholePlay`；记录改为 file/played 的 loudness+peak，typical 按歌曲 key 去重；文件分析改用 22.05kHz + Folia K-weighting/gated loudness；播放中按规则 ramp/hold。
- **防回归**：不要把“常量一致”当成算法一致；修改平衡时先核对 Folia 的输入顺序、记录结构和 mover 返回值。

## 67. 在线平台增益走 stream 头，缓存重播会丢

- **防回归**：不要用平台名硬编码“有增益”；只有真实字段才进 `platformDb`。

## 68. profile 不是“有字段就算对齐”

## 69. 缓存命中会绕过平台增益

- **现象**：分析字段/算法升级后，旧 `music.profile.v1` 仍被平衡读取，结果和当前 `trackProfile` 不一致。
- **原因**：存储对象没有版本校验，字段齐全就被当成有效。
- **处理**：完整 profile 带 `TRACK_PROFILE_VERSION`；`profileFor` 在版本存在且不匹配时返回 null，让 `analyseTrack` 重新生成。
- **防回归**：算法版本变化时同时更新 bundle 和 profile 版本；不要只改分析代码。

## 75. 有 profile 不等于 crossfade 会用

- **现象**：profile 已存 bpm/beatOffset，`planBlendShape` 仍传 `nextBeatIn: null`，过渡没有卡拍。
- **原因**：消费端没有把 profile 的拍点相位换算成 incoming 的下一拍时间。
- **处理**：`prepareCrossfade` 用 `bpm`/`beatOffset` 计算 `nextBeatIn`，把 `planBlendShape` 的 `overlap` 写回计划。
- **防回归**：新增 profile 字段后要同时接线消费端；只存不用等于没做。

## 76. 在线下一首 profile 不要为了分析而下载

- **现象**：为了尽早给在线下一首做 profile，直接 `fetch` 它的 stream URL，会在未缓存时触发整首下载。
- **原因**：`streamUrl` 在缓存 miss 时会解析 CDN 并代理，不是本地读取。
- **处理**：先请求 `/online/cache-info`；只有 `cached: true` 才读 `streamUrl`，否则等跨淡预取 blob 或跳过。
- **防回归**：profile 调度不能成为隐式下载入口；分析字节必须来自本地文件、已缓存媒体或已有 blob。

## 77. key 关系只缩放长度，不是调性匹配

- **现象**：crossfade 读了 keyRelation 就以为做了调性匹配。
- **原因**：Folia 的 key 规则是不给冲突和声时间（缩短 overlap），不是移调；移调需要真实 pitch shift，会毁掉整段混音。
- **处理**：只按 Folia 的 `LENGTH_SCALE` 缩放 overlap；不把 key 写进 pitch/gain。
- **防回归**：clashing 只允许缩短，不允许改调；不要用 key 伪造 stem handover。

## 78. style 计划要真的传给 transport

- **现象**：`chooseTransitionStyle` 选出了 bassSwap/tailRide，crossfade 仍传 `hold: 0, together: 0`，听感还是纯 crossfade。
- **原因**：planner 只给了计划，执行端没有消费 `hold/together/crossover`。
- **处理**：`prepareCrossfade` 把 `shapeBlend` 结果写进 `xfadePrepared`，`beginCrossfadePlayback` 传给 `crossfadeTo`；beatCut 允许 0.02 秒级窗口。
- **防回归**：planner 的输出字段必须逐个有执行端；只算不传等于没接。

## 79. automix profile 不能绑在音量平衡开关上

- **现象**：关闭智能平衡后 crossfade 也没有 bpm/key/sections，因为 profile 分析被 `normalizeVolume` 提前 return 掉了。
- **原因**：profile 消费端是 automix，不是音量平衡；两者只是共享测量结果。
- **处理**：关闭平衡时仍异步分析 profile，但立即 `finish()`，不阻塞播放；分析完成后再调度下一首。
- **防回归**：profile 分析是否运行由 automix/crossfade 需求决定，不能由音量平衡开关决定。

## 80. 在线首音不能等整首 blob 和分析

- **现象**：同一首在线歌，Folia 很快出声，本插件长时间停在加载。
- **原因**：`fetch(...).blob()` 等完整响应，然后解码整首、跑 profile，`playAfterLoudness` 等分析结束才 `play()`；平台/网络不是根因。
- **处理**：在线当前曲直接 `audio.src = Host /online/stream`，立即 resolve 播放门；profile 只在媒体缓存命中时后台补，平台增益后台 HEAD 取。
- **防回归**：不要把完整下载、完整解码或 profile 放回首音关键路径；桌面 seek 若回归，应用 Range/MediaSource 解决，不要恢复整首 blob。

## 81. 200 响应会让 seek 回开头

- **现象**：在线歌曲拖到中间又跳回开头；首音正常。
- **原因**：媒体元素 seek 会发 Range 请求；CDN/Host 若回 200 而不是 206，Chromium 把它当不可 seek 流，重置到 0。旧 blob 方案通过本地随机访问绕开了它。
- **处理**：Host 缓存已解析 CDN URL，Range 请求复用同一对象；CDN 对 `bytes=0-` 回 200 时直接标记为完整 206，对后续 start>0 的 Range 读取全量并切片为 206 + `Content-Range`；`preload=auto` 让浏览器提前缓冲。
- **防回归**：不要只检查 `Accept-Ranges`；必须检查 seek 请求的响应状态是 206 且 `Content-Range` 正确。

## 82. 代理 Range 再准，也不如 MediaSource 可控

- **现象**：Host 已返回 206/Content-Range、固定 CDN URL、preload=auto，在线 seek 仍回开头。
- **原因**：媒体元素播放的是 Host 代理 URL，Chromium 对代理资源的 seekability 判断不等价于 CDN 原生资源；旧 blob 能 seek 是因为本地随机访问。
- **处理**：当前曲改用 MediaSource，Host 字节流 append 到 SourceBuffer，seek 由客户端 buffered ranges 决定；不支持 MSE 的格式回退直连。
- **防回归**：不要再通过加响应头“修”代理 seek；MSE 的 seek 必须等 `buffered` 覆盖目标或保留 pendingSeek。

## 83. MSE 的 duration 是已 append 前缀

- **现象**：总时长显示 0/1:38 时拖到 90%，加载完整后却停在不到一半。
- **原因**：MSE 的 `audio.duration` 只覆盖已经 append 的媒体，不是整首；seek bar 用它当最大值，90% 实际是“已加载前缀的 90%”，随后又被 `api.seek` clamp 到该前缀。
- **处理**：UI 使用 `max(media duration, 歌曲已知 durationSec)`；sourceopen 时把 `MediaSource.duration` 设为整首时长；`api.seek` 对 MSE 使用已知整首时长作为上限。
- **防回归**：不要把 MSE 的 growable duration 当最终总时长；没有已知 durationSec 时不要用加载前缀做百分比 seek。

## 84. octet-stream 会让 MSE 静默回退

- **现象**：MediaSource 代码已接，但拖动仍回开头；实际走的是直连回退。
- **原因**：CDN 返回 `application/octet-stream`，`MediaSource.isTypeSupported` 为 false，`playOnlineMse` 回退 `playOnlineDirect`；Host 又把泛类型原样转给浏览器。

- **防回归**：MSE 回退要看 MIME 和回退原因；不能只看首音是否正常。

## 89. 在线歌曲播不出来，toast 只有一串 DEMUXER_ERROR（在线源 / 取流）

- **现象**：海外网络点播网易云稳定失败，toast 是 `PipelineStatus::DEMUXER_ERROR_COULD_NOT_OPEN: MediaSource endOfStream…`；同一首歌手工换成另一个 CDN 节点就能播（issue #26）。
- **原因**：平台给 `/song/url/v1` 签的是**某一个** CDN 节点的地址，节点会因为请求来源 IP 拒绝（403），文件本身没问题；而路由只给酷狗的 404 写了重试，别的平台直接 `fail(502,'UPSTREAM_FAILED','HTTP 403')`。更关键的是客户端：非 2xx 只拿到状态码就降级 `startOnlineDirect()`，把**同一个 502 地址**塞进媒体元素，Chromium 把 JSON 错误页当音频，于是 Host 写好的 `error.message` 被内核文案顶掉。
- **处理**：路由对 403/404/408/429/5xx 先删缓存重新要一次签名地址（换节点），仍失败再降一档音质，最终把状态码写进文案并带 `upstreamStatus`；客户端先读 `error.message` 走 `onError` 并停下、**不降级直连**；`onError` 把浏览器 pipeline 文案换成 `page.playbackFailedMedia` 且只留在日志。
- **防回归**：`test/host/online-stream-fallback.test.mjs` 断言 403 会重取一次（同音质）再降档；`test/client/online-stream-errors.test.mjs` 断言原因被读取、拒绝分支不落回直连、内核文案被过滤。Folia 的做法见 `handleOnlineMediaFailure.ts`（媒体失败→再要一次地址）与 `onlineFailureTexts.ts`（分类文案，内核原文只进日志）。

## 95. CDN 把 FLAC 标成 audio/mpeg，MSE 按标签解封装会失败（在线播放 / MIME）

- **现象**：海外（荷兰）网易云无损 / 高解析档一播放就报「音频无法解码，取流地址可能已失效」；标准 / 较高档正常。CDN 返回 200/206、内容是合法 `fLaC`，但 `Content-Type` 是 `audio/mpeg`。
- **原因**：Host 的 `onlineAudioMime` 只要上游是 `audio/*` 就原样透传；客户端 `MediaSource.isTypeSupported('audio/mpeg')` 为真，于是把 FLAC 字节 append 进 MP3 SourceBuffer。Folia 不做这层代理/MSE，它把 URL 交给媒体元素，Chromium 自己按字节嗅探容器，所以没有这个失败。
- **处理**：Host 在写响应头前读取首个 chunk 嗅探容器（`sniffAudioMime`），实时流与媒体缓存副本都优先用嗅探结果；只在请求起点为 0（无 Range 或 `bytes=0-`）时嗅探。客户端保留 MSE 的 seek 能力，但在 MSE 解码失败时按 Folia 的直连路径回退一次。
- **防回归**：`test/host/online-stream-fallback.test.mjs` 的 FLAC-as-mp3 用例断言 `content-type: audio/flac` 且首块仍写入；不要只信 `content-type`，也不要在 Range 起点非 0 时嗅探（那是文件中间，会误判）。

## 97. 两个增益变量在同一个节点上相乘

## 109. 长音频走 MSE 撞 12 MiB 配额，回退直连后停在 0:00

- **现象**：网易云等在线源的长曲目（约 6 分钟以上的 320 kbps MP3）点播放后队列停在这首歌，进度始终 0:00；没有明确报错，也不自动跳下一首，重启 DSH 无效（issue #31）。
- **原因**：`playOnlineMse` 的 `read()`/`pump()` 没有背压，整首约 15.4 MiB 的音频被快速 append 进 SourceBuffer，超过 Chromium 约 12 MiB 的音频配额后抛 `QuotaExceededError`；`fallbackToDirect()` 只切换到直连，没有恢复已经被 `playAfterLoudness()` 置为 false 的 `pendingAutoplay`，直连流有效却仍处于暂停态。因为没走 `onError`、直连也没 error/ended，`autoSkipUnplayable` 不触发。
- **处理**：响应总字节超过 10 MiB 时直接走直连媒体元素（`mpMseStreamTooLarge`）；MSE 任意失败回退时用纯函数 `mpFallbackPlaybackState` 保留播放意图和当前进度；补 `SourceBuffer` 的异步 `error` 监听。直连/Range 请求在 Host 侧只允许同音质重签名，避免海外节点重试时中途降档把不同编码拼进同一个资源；客户端用 `direct=1` 标记直连。
- **防回归**：`test/client/mse-fallback.test.mjs` 测大小阈值、Content-Range 总长、播放意图/进度；`test/host/online-stream-fallback.test.mjs` 增加 Range 与 `direct=1` 不降档用例。

## 110. 在线直连代理流拖动进度条又回到开头

- **现象**：部分在线歌曲（大文件、FLAC/MSE 不支持、MSE 失败后的直连回退）能正常播放，但拖动进度条后会从 0:00 重新播放；本地文件正常。
- **原因**：直连回退把 Host 代理的 HTTP 流直接交给 `<audio>`；Electron 媒体栈在 readyState 已满时会把 `currentTime` 写入丢掉，Chromium 对代理资源的 seekability 也不等价于 CDN 原生资源（见第 82 条），于是 native seek 回到 0。
- **处理**：`startOnlineDirect` 改为 `startOnlineBlob`：整段 `fetch` 成 Blob，`loadActiveSource(blob URL)`，媒体元素对本地对象做随机访问；缓存命中、大文件、MSE 不支持/MSE 失败都走它，MSE 仍负责未缓存短音频的流式起播。
- **防回归**：`mse-fallback.test.mjs` 断言回退使用 Blob；`online-stream-errors.test.mjs` 保持“拒绝流不直连”的守卫。代价是直连回退先下载完整文件再起播。

## 111. 外观页的滑杆拖不动 / 滚轮像没反应（播放卡片 / 滑块）

- **现象**：播放卡片「外观」页的样式参数滑杆按住拖动只走一格，松开再按才动一步；滚轮每格只挪 1 个 step（对比度这类 step=0.01、滑杆约 70px，一格不到 1px），看起来完全没反应。底栏音量滑杆两者都正常。

- **防回归**：`volume-control.test.mjs` 断言 5% 步进与共享 hook；`sheet-pages.test.mjs` 断言 `TuningRange` 声明位置在 `PlayerSheetInner` 之前（模块作用域）。

## 121. 酷狗歌单滚到后面整页重复（在线音乐 / 分页游标）

- **现象**：酷狗「我喜欢」歌单往下滚，之前出现过的歌按原顺序又出现一遍（实测 258 首的列表，翻页后同一批歌反复出现）。
- **原因**：`getMyPlaylistSongsPage` 用 `nextOffset = at + songs.length`，而 `songs` 是 normalize 之后剩下的行。第 1 页 100 行里有一行没有 hash 被丢掉 → `nextOffset` 99；下一次 `page = floor(99/100)+1 = 1`，又把第 1 页取了一遍。客户端合并时读的是 Host 行上根本不存在的 `path`，于是整页被当成新歌追加。实测：raw page 100 行 → KGL 99 行 → next 99 → offset 99 请求返回的正是第 1 页（99 行全部重复）。

- **防回归**：`kugou-playlist-ids.test.mjs` 新增「坏行不缩短游标」「上游压页大小仍按实际 stride 取第 2 页」两段；`test/client/online-song-key.test.mjs` 钉住身份、页内去重、合并键与游标守卫。

## 123. 汽水「Qishui rejected the request」：车机 ticket guard 过期（在线音乐 / 汽水）

- **现象**：汽水音乐的歌单页「加载失败 · Qishui rejected the request」；搜索还正常，只有账号类读取（歌单、喜欢的歌、最近播放）失败。
- **第一性事实**（真实会话直接调包）：`search` 正常；`liked_songs` / `user_playlists` / `recent_played` 全部 `auth-required`、`upstreamCode=28001008`；存下来的会话 `expiresAt` 比当前时间早 **204 小时**（约 8.5 天）。
- **原因**：汽水的账号请求走 ticket guard（`bd-ticket-guard-*` 头），票据约 6 小时过期，过期后平台回 28001008。包里的续期只挂在 `login_status`（`auth.status()` → 刷新 access_code → 新 ticket → `/me/info/` 验证 → `sessions.set`），我们的 `request()` 从不调用它，平台原句就直接冒到页面。Folia 的桌面桥是原样透传，同样没有续期这一步。
- **处理**：`src/host/providers/sources/qishui/index.js` 的 `request()` 在账号读取失败且 `code=auth-required`、`upstreamCode` 非空时，先调一次 `login_status` 续期（续期会把新会话写回 sessions 存储），成功则**重放原请求一次**；续不上（无会话/被拒）给「汽水登录已过期，请在「设置 → 在线」重新扫码登录」，不再把平台原句直接给用户。`login_*` 操作自身不触发续期，避免循环。

- **防回归**：`test/host/qishui.test.mjs` 断言「auth-required → login_status → 重放」的调用序列，以及续期不可用时的中文提示与公开搜索不受影响。

## 124. 播放模式是一颗按钮，随机是模式且原顺序要能还原（播放器界面）

- **规则（产品确认，不是 Folia）**：顺序播放 → 单曲循环 → 随机播放 → 顺序播放，始终一颗按钮（底栏、播放页胶囊、播放页右侧同一套）。音频设置里不再有第二套「播放模式」控件。
- **状态**：`state.queue` 是"正在播放的顺序"，`state.baseQueue` 是原顺序，`state.playMode` 是模式（`sequence/one/random`）。随机时 `queue = [当前歌, ...其余随机]`；切出随机（顺序或单曲）按 `baseQueue` 还原，并把 `index` 指回正在播的那首；再次进入随机**重新生成**一张表（不复用上一张）。随机表放完一轮按 `loop='all'` 回到表头循环，**不自动重洗**；重启保留当前随机表与 baseQueue（`playback.json` 的 `playMode/queue/baseQueue`，Host `sanitizePlayback` 兼容旧 `loop/order` 并迁移）。
- **队列编辑**：非随机模式下 `move/reorder` 同步写 baseQueue；随机模式下拖拽只改随机表、不动原顺序；增删歌两边同时同步。
- **模式唯一入口**：页面「随机播放」= `setPlayMode('random')` 后按随机表开播；「一轮不重复」只影响下一张随机表的排列（`shuffleForRound`），不再自动重洗。
- **与 Folia 的差异**：Folia 的随机是一次性 `shuffleQueue` 动作、没有"切回顺序还原"；这里按产品要求做成模式 + 原顺序还原，**不要照 Folia 拆回去**。
- **防回归**：`test/client/panel.render.test.mjs` 断言按钮 顺序→单曲→随机→顺序、`playMode/loop` 对应、随机时当前歌第 0 位且 baseQueue 不变、切出随机队列还原 A B C D 且当前歌不跳、再次进入随机仍基于原顺序；Host `test/host/playback.test.mjs` 断言 `playMode/baseQueue` 的保存与默认值。

- **登录态要重扫码**：旧 `sessions.json`（明文）与移植源的 `<平台>-legacy-store.json` + `<平台>-seal.key`（AES-256-GCM）不是一套格式；歌曲 id 未变，收藏/歌单/历史不受影响。
- **防回归**：`bodian-folia-source` / `qishui-folia-source` / `qq-folia-source` / `netease-folia-source` 四个测试，以及 `build-folia-source.mjs --check`（已并入 `npm run check`）。

## 131. Folia 镜像目录重构为单根 1:1（工程结构）

- **为什么**：镜像原来分在两套前缀（`src/folia/` 对应上游 `src/`，`src/folia-mods/` 对应上游 `sources/`、`packages/`），每次移植都要想路径怎么摆；且没有脚本能发现镜像里混进上游不存在的文件、或内容悄悄漂移。
- **现在**：镜像统一在 `folia/`，与上游仓库根 1:1：`folia/src/**`、`folia/sources/<id>/**`、`folia/packages/<包>/**`。镜像是最小子集；上游多出来的文件不搬（`--list-missing` 可查）。替换上游模块的替身在 `src/folia-adapters/<上游相对路径>`，文件头写「替身上游：…」。
- **校验**：`node scripts/check-folia-mirror.mjs`（已并入 `npm run check` 与 `npm test`）。默认要求逐字节相同；确有插件适配的 52 个文件登记在 `folia/mirror.manifest.json`（含登记时的上游 SHA256，上游一变就报错）。**不要**为了让校验通过去改清单里没登记的文件——先判断是「上游漂移该刷新」还是「需要适配该登记」。
- **已知取舍**：这 52 个文件集中在 `src/components/visualizer/**` 与主题/样式相关（React 18 shims、pixi/three 适配、图标与 i18n 接入），是插件运行所必需的适配；清单是这次重构时的一次性基线，之后新增差异必须逐条登记。

## 133. 在线播放的失败/试听对齐 Folia（三处）

- **为什么**：音源层早已原样移植，但宿主层还留着自写规则：试听提示靠“播起来后时长不足一半”判断、`autoSkipUnplayable` 默认开、失败只有一句笼统提示。
- **试听**：上游的 `getAudioSource` 会把试听片段标成 `preview: true`，宿主在播放前据此提示。插件里浏览器只拿 `<audio src>`，读不到这个标记，所以新增 `/online/stream-info`（只解析、不转发字节，复用 Host 的 `streamUrlCache`）让客户端播放前先问一次；客户端据此在出声前弹 `online.previewOnly`。**顺序**：先问 `/online/cache-info`，命中缓存就直接播（缓存是整曲播完后写的，不能被平台问询挡住），未命中才过这道门。
- **自动跳过**：Folia 的 `autoSkipUnplayable` 默认 `false`（`useAudioSettingsStore` 的 `getStoredBoolean(..., false)`）；插件改为同默认，老用户的已存值不变。
- **失败分类**：`src/host/services/playback/online-failure.js` 是 Folia `onlineFailureCase.ts` 的规则移植（case 名与 stops/retry/unplayable 同语义）。音源自己的说法经 `describeFailure` 拿到：bridge 在 `createFoliaSource` 末尾透传上游定义，酷狗经门面 `kugouFacade('describeFailure')`，`omni.describeFailure(sourceId, 'audio', error)` 统一取；没有这条规则的源回 null。**注意**：`createFoliaSource` 里给 `source` 加方法必须放在 `const source = {...}` 之后，否则 `Cannot access 'source' before initialization`。
- **别丢的细节**：`/online/stream` 失败响应仍保留 `error.code`/`error.message`（客户端老路径在读），只额外加了 `error.case`；`stream-info` 永远 200，失败用 `ok:false` 让客户端决定停还是跳过。
## 134. 试听片段的时长与歌词时钟（对齐 Folia）

- **为什么**：上游把「平台只给试听」当成媒体文件本身处理：舞台时长读媒体元素，歌词时钟是 `currentTime + clipStartMs`。插件原来把时长算成 `max(媒体, 目录)`，试听时永远显示整曲长度，进度条按整曲走；歌词时钟也没加片段起点。
- **时长**：`src/client/services/player/duration.js` 的 `effectivePlayerDuration(mediaDuration, trackDuration, preview)` 在 `preview === true` 时返回媒体时长（没有才退回目录）。播放器在 `onTime` 里（`session.preview` 时）从 `audio.duration` 同步 `state.duration`；MSE 只报已追加前缀时用 `audio.buffered` 末端兜底。所有显示时长的地方（播放页、胶囊、进度条、传输胶囊、状态栏、p3 面板）都把这个 `preview` 传进去。
- **歌词**：Host `/online/stream-info` 返回 `clipStartMs`（`bridge`/酷狗门面从上游 `getAudioSource` 的 `clipStartMs` 透传；音源没给就是 0）。客户端 `session.clipStartMs` → `getTime()`/`getPlaybackTime()` → 播放页 `lyricClock(currentTime + clipStart)`、两套 Folia 舞台的 `readTime()`、作曲栏与状态栏；舞台歌词行点击 seek 用 `- clipStart + offset` 映射回元素时间。
- **续播**：试听片段不要恢复整曲保存位置——`applyDirectSavedStart` 与 MSE 的 `applySavedStart` 都先判断预览并清掉 `pendingResumeSeconds`。注意 `playOnlineMse` 内部有同名局部变量 `session`（MSE 会话），模块级播放会话要用 `isPreviewSession()` 读，否则判断永远拿不到 `preview`。
## 135. QQ 播不了：取流只带 id，songmid 丢了

- **现象**：QQ 歌点播放提示「无法播放：QQ song has no songmid」。Folia 能放。
- **第一性事实**：QQ 的播放键不是 id。上游 `qqNormalize` 把数字 songid 放进 `publicId`（本插件 DTO 的 id 就是它），songmid 放进 `lyricIds.qq` 与 `data.songMid`，`mediaMid` 在 `data.mediaMid`；`qqProvider.getAudioSource` 先取 `qqSongMidOf(song)`，没有就抛这条错。Folia 的宿主 RPC 传的是**整首歌对象**，所以有侧车。本插件的 `/online/stream?provider=&id=` 只有 id，`foliaSongOf({ id })` 造出来的歌没有 data/lyricIds。
- **同类隐患**：波点 `data.freeSign`（免费曲）、酷狗 `data.albumId`/`albumAudioId`/`variant=cloud` 也都不在 id 里；酷狗门面本来有个内存 `cache.js` 记完整对象，但重启就没了。
- **做法**：`song-registry.js` 在 `dto.songOf` 交出歌时记侧车（provider+id → data/lyricIds/variant），落盘 `online-songs.json`；bridge 的 `fullSongOf`（取流、歌词、点赞、歌单写）与酷狗 `cache.foliaSongOf` 找不到完整对象时从注册表补。侧车是**取流/写操作的输入**，不是展示数据，所以只存这几项。
- **别踩**：`bridge.js` 里用 `replace_all` 把 `foliaSongOf(song)` 换成 `fullSongOf(song)` 时，会连 helper 自身的第一行一起换掉 → 无限递归；helper 内部必须继续调 `foliaSongOf`。测试 `test/host/song-registry.test.mjs` 用假 QQ 定义重现了这条错误信息，改坏会立刻红。
- **清理**：新文件归 `plugin-data.js` 的 `cache` 分类（清空插件数据会删），注册表测试里用 `clearDataCategory(dir,'cache')` 验证。
