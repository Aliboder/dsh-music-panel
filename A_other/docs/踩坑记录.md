# 踩坑记录

每条先给一句「原因会导致后果」，下面列出具体原因、现象与处理；改代码/发布前先全文搜一遍。

---

## 1. Folia 用 React 19 的 ref prop，宿主 React 18 会导致背景不随音乐扭曲。
- 原因：Folia 跑 React 19，函数组件把 ref 当普通 prop 透传；宿主固定 React 18.3.1， memo(function …) 不转发 ref。paperShaderMount 恒为 null，latent 里逐帧的 setSpeed / u_distortion / u_swirl / u_pxSize 全被 if (currentMeshMount) 跳过。
- 现象：隐现（流体/混合）只有缓慢流动，没有鼓点形变；暂停后背景仍按原速动。
- 处理：vendored src/render/folia/vendor/paper-shaders-react/dist/shaders/*.js 的 7 个 包装改为 memo(forwardRef(function …))，并把 ref 传给底层 ShaderMount；重建 backgrounds.bundle.js。

## 2. 背景/样式是独立 bundle，只重建 client.js 会导致画面仍是旧版。
- 原因：backgrounds.bundle.js、styles.bundle.js、pendolo.bundle.js 是独立产物， node scripts/build-client.mjs --check 只校验 client.js 的拼接，不会发现 bundle 过期。
- 现象：改了背景/样式源码并重启，画面还是旧的；client.js --check 却通过。
- 处理：改背景源码或 vendor/paper-shaders* 后，顺序固定为 node scripts/build-backgrounds.mjs → node scripts/build-client.mjs。 时计/样式同理：build-pendolo.mjs / build-styles.mjs。

## 3. 把 bands 归一化成 0..1 会导致背景鼓点完全不动。
- 原因：Folia 背景用 useTransform(spring, [10, 200], [0.95, 1.45])，输入必须保持 0–255； 0..1 永远落在映射的第一档。
- 现象：背景有轻微流动，但鼓点完全不起作用。
- 处理：process(v, boost) = (v / 255) boost * 255，五条 band 与 audioPower 都输出 0–255 （见 src/render/styles/folia-audio.js）。

## 4. analyser smoothing 设 0.82 会导致鼓点被抹圆、声音发钝。
- 原因：插件旧 analyser smoothingTimeConstant = 0.82，Folia 是 0.6；额外平滑把鼓点抹圆。
- 现象：低频段有值，但鼓点看起来总是被抹圆。
- 处理：src/50-player.js 改为 0.6。插件自己的频谱条会做峰值归一化，不会因此变噪。

## 5. 不给 audioBands.spectrum 会导致莫奈频谱退化成五段插值。
- 原因：没提供 audioBands.spectrum，Monet AudioOverlay 回退到五段 band 插值。
- 现象：莫奈样式的底部频谱条只有几段高低，没有细密频谱。
- 处理：每帧 new Uint8Array(wave) 写入 spectrum。不要直接复用 analyser 的 buffer （下一帧会覆盖已经发给 MotionValue 的值）。

## 6. 误以为暂停应完全冻结会导致观感与 Folia 不一致。
- 原因：Folia 的隐现暂停时是 base × 0.12，不是 0，观感是「几乎停住」，不是完全冻结。
- 现象：按暂停后背景还在很慢地动。
- 处理：先确认第 1 条的 ref 是否生效；12% 慢速符合上游行为，不要当 bug 修。

## 7. 以为所有背景都吃音频会导致误判音频分析坏掉。
- 原因：只有 隐现（latent） 与 通用（common，几何图形） 吃音频。莫奈/漫游/空/嵌入 在上游就是封面或时间驱动，静止是设计如此。
- 现象：切到莫奈/漫游/空/嵌入后，鼓点没有反应，以为音频分析坏了。
- 处理：想测音频响应就用隐现（流体/混合）或通用；不要把其他背景的静止当 regression。

## 8. 旧 ambient 回响层残留会导致刷新后仍是旧背景。
- 原因：旧 ambient 背景的封面回响层（.mp-np-bg 的 is-echo）还在运行中的旧 client 里； 新播放页不再渲染它。
- 现象：刷新/重启后播放页仍是旧 ambient 背景，和新代码不一致。
- 处理：重启 DSH 或刷新页面；确认 client.js 是新的（安装目录里的哈希/关键字符串）。

## 9. 保留「暂无歌词」占位会导致纯音乐画面被文案挡住。
- 原因：两处占位（src/ui/04-now-playing.js、src/ui/04-player-page.js）及对应 CSS 已移除。
- 现象：纯音乐/无歌词时，播放页中央出现占位文案，挡住视觉器。
- 处理：page.noLyrics 的 i18n key 仍保留，暂未使用；不要再把占位加回来。

## 10. 浅色主题卡片没做深色岛 token 会导致白底白字。
- 原因：卡片背景固定为深色玻璃（rgba(23,23,26,.95)，属于深色岛），但内部控件读的是宿主 token（--dsw-alias-bg-layer-2 等）；浅色主题把它们解析成近白表面/深色文字。
- 现象：浅色主题打开播放页的播放器卡片，圆角块、胶囊、输入框、页签变成白底白字， 文字几乎看不见；深色主题正常。
- 处理：在 .mp-card 作用域把用到的 token 钉成深色值（与 .mp-np 的深色岛一致）， 新浮层照此办理；不要逐个子组件打补丁。

## 11. 主题守卫不扫新 UI 与内联圆角会导致违规样式漏过测试。
- 原因：test/theme.test.mjs 的字号检查只扫手写的 uiFiles（到 16-header.js）； 圆角检查只扫 90-theme.js 的 CSS，内联 borderRadius 根本没查。
- 现象：在 20-player-sheet.js / 25-look-picker.js 里写了 borderRadius: '10px'、 fontSize: '11.5px'，npm test 仍然通过。
- 处理：新增 src/ui/*.js 时把文件名加进 uiFiles；内联圆角也按 8/12/16/20 写。 扩大守卫前先清旧违规（卡片里还有 10px / 11.5px 等历史值），不要一次性打开。

## 12. 只测 native 宿主组件会导致 fallback 控件缺失或错位。
- 原因：hostUi 加载失败时 hostComponent 返回 null，走本地 fallback；测试环境固定 fallback，但本地只验证了 native。
- 现象：真实 DSH 里控件正常，测试/harness 或旧版 DSH 里控件缺失、错位、无法点击。
- 处理：native 和 fallback 都看一遍；看控制台 host UI kit: native|fallback 和设置页状态行； fallback 保持同 DOM/class/props，不另起一套外观。

## 13. profile 装的是 tarball 副本而非工作区 link 会导致改源码不生效。
- 原因：profile 里的插件可能是从 tarball / file: 安装的副本，不是工作区 link； 工作区构建只改仓库的 client.js。即使是 link，Host 模块也要重启才会换新的模块代际。
- 现象：重新 build-client、刷新页面，界面还是旧逻辑。
- 处理：开发期用 link 安装；交付前 npm pack 后重新安装。装完刷新客户端加载新 client.js，完全重启 DSH 加载新 Host。

## 14. blockExoticSubdeps 拦截 GitHub tarball 会导致 install_bundle 失败。
- 原因：package.json 里 kugoumusicapi 是 GitHub tarball URL；DSH 的 pnpm 供应链策略 默认禁止子依赖里的 exotic dependency。
- 现象：在 profile 里安装/更新插件时报 Exotic dependency "kugoumusicapi" (resolved via url) is not allowed in subdependencies when blockExoticSubdeps is enabled。
- 处理：本地临时用 pnpm add <tgz> --config.block-exotic-subdeps=false --ignore-scripts 安装； 发布前必须解决（换成 registry 包，或让安装器允许该依赖/改为可选依赖），不要把这个参数 当正式安装方式。

## 15. 同版本重打包不换已装文件会导致改动装不进去。
- 原因：hoisted linker 认为该版本已安装，只补依赖；或 store 命中了旧内容。
- 现象：重新 pack 覆盖同名 tarball，pnpm add 成功、lock 的 integrity 也变了，但 node_modules/dsh-music-panel 里还是旧文件。
- 处理：删掉 node_modules/dsh-music-panel 后按 tarball 重新解压/安装，或升版本号； 装完用关键字符串/哈希确认 client.js 是新的。

## 16. 递归删除 Windows junction 会跟随链接会导致误删源码。
- 原因：Windows junction 在某些递归删除/资源管理器操作里会被跟随。
- 现象：清理 node_modules/dsh-music-panel 时，把链接目标（工作区仓库）一起删了。
- 处理：先 Get-Item 确认 LinkType=Junction，用 cmd /c rmdir "<path>" 只删链接； 删完确认目标仓库还在。

## 17. 未停插件就卸载会导致数据被运行中的进程写回。
- 原因：插件仍在运行，播放/切歌会写回；关闭窗口时 client 的 beforeunload 还会 flushOnHide() 保存当前队列。
- 现象：删了 ~/.dsh/music，几秒后又出现 playback.json / cache；重启后旧队列还在。
- 处理：先用 plugin_manager 停用插件，再删数据；重装后先刷新页面丢掉旧队列，再退出重启。

## 18. 渲染层 localStorage 不随卸载清除会导致重装后偏好仍在。
- 原因：music.prefs.v2、dsh-music.prefs、music.startupGuide.intro.v1 在 DSH 渲染进程 的 localStorage，不在 ~/.dsh/music；普通卸载不会删（与宿主行为一致）。
- 现象：重装后仍记得歌词样式、主题、引导已读。
- 处理：需要真正首次体验时，在 DSH DevTools 里 removeItem 这几个 key 再 reload； 不要以为删数据目录就能清掉界面偏好。

## 19. 使用不存在的 --st-raise 变量会导致选中色改了没反应。
- 原因：仓库里没有任何 --st-raise: 定义；var(--st-raise, rgba(255,255,255,.18)) 永远走 fallback。
- 现象：想用 --st-raise 调选中胶囊的抬升色，改了没反应。
- 处理：深色岛用白色 alpha，主题化用业务 token / color-mix；不要依赖未定义变量。

## 20. 手工 insert 与 bundle selection 状态不同步会导致插件管理器显示错误。
- 原因：正常安装是「依赖 + dsh.profile.bundles 选中 → 包内 cordis.patch.yml 插入」； 手工在 profile 的 cordis.patch.yml 写 - insert: id: music 会绕开管理器。set_plugin 禁用又会在 patch 末尾追加 - id: music + disabled: true，是另一层覆盖。
- 现象：插件能跑，但插件管理器显示「已停用」；或删了 insert 后重启状态又不对。
- 处理：按 install_bundle 的形态安装：依赖 + dsh.profile.bundles，不要手工 insert； 清理时全文搜 music，同时处理 insert 和末尾 override。

## 21. 只重建 client.js 会漏掉独立生成物会导致样式/歌词仍旧。
- 原因：client.js 是 src/ 的 fragment 拼接产物；独立生成物还有 lyrics.bundle.js、styles.bundle.js、backgrounds.bundle.js、pendolo.bundle.js、 folia-tailwind.js、vendor/*.bundle.js、lib/assets/icu-folia/*.json.gz。
- 现象：改完源码，build-client --check 通过，但样式/歌词/背景还是旧的。
- 处理：按 AGENTS.md 的命令先重建对应 bundle，再 build-client；icu-folia 需要 folia-major-main 检出。不要直接改生成物。

## 22. fragment 顶层声明重名或重复扫描 .bundle.js 会导致重复声明报错。
- 原因：client.js 是 src/ 拼接的单个 IIFE，所有 fragment 共享作用域，顶层 var/function/const 必须唯一；.bundle.js 是独立产物，构建时跳过重复扫描，不受这条约束。
- 现象：构建后浏览器报 Identifier '…' has already been declared，或新 fragment 的函数被同名旧声明覆盖。
- 处理：新增顶层名一律带 mp 前缀并先搜同名；改 .bundle.js 走对应 build-* 脚本，不要直接改 client.js。

## 23. 只改 folia-tailwind.css 而配套 .js 产物没变会导致样式仍旧。
- 原因：Tailwind 有两份。.css 是生成结果，client.js 实际注入的是 folia-tailwind.js 里的字符串；仓库目前没有专门生成这份 .js 的 build 脚本。
- 现象：改了 src/render/folia/folia-tailwind.css，刷新后样式没变。
- 处理：改 Tailwind 后同步把新 CSS 写进 folia-tailwind.js（保持现有字符串格式）， 或先补一个生成脚本；最后 build-client。不要只改 .css 当交付物。

## 24. 浏览器 IIFE 里用 Vite 的 import.meta.glob/相对资源会导致 404 或报错。
- 原因：插件运行在浏览器 IIFE，不是 Vite 构建；资源 URL 必须相对 document.baseURI 解析为绝对地址，也没有 Vite 的静态分析 API。
- 现象：样式里的图片、字体、背景 404；或代码用了 import.meta.glob 直接报错。
- 处理：用 new URL(path, document.baseURI).href；资源走插件导出或 /music/... 路由；不要依赖 Vite 专有 API。

## 25. 只信 player snapshot 的暂停状态会导致背景继续动。
- 原因：player snapshot 可能滞后；真实 <audio> 的 paused / ended 才是权威状态。
- 现象：按暂停后背景/频谱仍在动，或恢复播放时状态错位。
- 处理：暂停判断读 <audio> 的 paused/ended；暂停时停止写 bands（或写 0），恢复时重新启动。

## 26. VisualizerShell 不转发 ref 会导致心象尺寸为 0。
- 原因：VisualizerShell 必须 forwardRef 转发容器 ref；普通函数组件会丢掉 ref。
- 现象：心象样式的 ResizeObserver 尺寸为 0，画面不显示或错位。
- 处理：用 vendored 的 forwardRef 包装并转发到容器（与 paper-shaders 的 React 18 处理一致）。

## 27. 移除功能不做偏好迁移会导致老用户样式空白或回退错误。
- 原因：已移除功能的偏好没有映射到当前默认样式，或者迁移只改内存没写回。
- 现象：老用户升级后样式空白或回退错误；旧 classic / cappella / machi 仍然生效。
- 处理：在 src/30-prefs.js 的迁移里把旧 id 映射到 classic；旧默认 monet 仅迁移一次，用户主动选择后写入 lyricStyleChosen，新增移除功能保持同样行为并一次性写回。

## 28. 手改歌词/icu-folia 生成物会导致下次构建覆盖且难复现。
- 原因：src/utils/lyrics/ 是 Folia 上游逐字副本；src/render/lyrics/entry.ts 编成 lyrics.bundle.js；lib/assets/icu-folia/*.json.gz 来自 folia-major-main/dev/icuFolia，都是生成物； client.js --check 不会发现它们过期。
- 现象：改了歌词解析或词典，线上没变；手改 .json.gz 后又无法复现。
- 处理：改歌词源码后先 build-lyrics 再 build-client；重建词典跑 build-icu-folia （需要 folia 检出）；不要手改 lyrics.bundle.js 或词典。

## 29. providerStore 固定平台列表再配双登录库会导致波点登录成功仍显示未登录。
- 原因：providerStore 只认固定平台列表，setLogin('bodian') 被直接 return；同时 index.js 又建了第二个 createLoginStore 写同一个 sessions.json，两个缓存互相覆盖。
- 现象：Bodian 扫码成功，卡片还是“未登录”；重启后会话丢失。
- 处理：provider-store.js 接受 Bodian 等已登记平台；Bodian 的 sessions 通过适配器写同一个 store；删除第二个 createLoginStore。

## 30. 二维码没有取消与 TTL、状态不校验 key 会导致关窗后还能扫、一直转圈。
- 原因：客户端只清定时器，Host 没有取消 key；没有 TTL / 已扫码超时；/online/login/status 也不校验 key。
- 现象：关窗后重新打开，旧二维码仍有效；已扫码后一直转圈。
- 处理：/online/login/cancel + createLoginState.cancel()；启动时带回 expiresAt；客户端的过期/已扫码 60 秒超时；Host 对 key 不匹配返回 LOGIN_STALE。

## 31. Folia Tailwind 与 i18n shim 未适配会导致字幕硬边方块与 ui.waitingForMusic。
- 原因：两处都来自移植边界。① styles.bundle.js 的 i18n shim 之前是 identity（t(key)=>key），Folia 的 ui.waitingForMusic 在其语言表里是空串；② folia-tailwind.js 是 Folia 编译出的完整 Tailwind 表，但插件从未定义 Tailwind 的主题变量（--spacing、--blur-2xl、--radius-*、--text-* 等），所有引用它们的工具类在浏览器里整条失效…
- 现象：切歌后底部歌词（字幕）后面出现矩形背景色块；歌词还没加载时屏幕中央显示 ui.waitingForMusic。
- 处理：shim 改为走插件字典（未知 key 返回空串，见 src/folia/shims/i18n.ts）；src/folia/folia-css.js 开头补上 Tailwind v4 的默认主题变量。字幕背景本身是 Folia 的「字幕背景」设置（默认开），已接入 prefs.subtitleOverlayBackground 并在设置里可关。

## 32. DSH 从 profile 副本加载插件会导致重启后仍是旧构建。
- 原因：DSH 从 <DSH_HOME>/profiles/<profile>/node_modules/dsh-music-panel 这个真实副本加载插件，桌面版的副本由 local-packages/*.tgz 安装而成；仓库里的改动不会自动进去。web profile 的同一路径是指向 desktop 副本的 junction，所以更新 desktop 副本就同时覆盖两者。
- 现象：仓库里改完、测试全绿、client.js 也重建了，重启桌面版后界面还是旧的（例如 Folia 样式仍显示 ui.waitingForMusic、字幕背景仍是硬块）。
- 处理：node scripts/install-local.mjs desktop（先校验 client.js 是最新，再把旧安装备份到 ~/.dsh/backups/，然后复制 index.js / client.js / src/host / locale 等），之后完全退出 DSH 再启动；只刷新窗口不会重载 Host 插件。

## 33. 歌词加载器用裸 prefs 会导致全站歌词消失并抛 ReferenceError。
- 原因：src/client/services/lyrics/loader.js 里写的是裸 prefs.xxx，但 prefs 只是各组件里的 var prefs = usePrefs()，不是全局；加载器调用时抛 ReferenceError，又被 load() 的 .catch 吞成空结果，于是「有歌词但没人拿到」。单测的 sandbox 恰好注入了全局 prefs，把问题遮住了。
- 现象：更新到含统一歌词加载器的构建后，播放页、卡片、播放条都不显示歌词；调试报告里 stage.lines=0、hasRaw=false，而 Host 的 /online/lyric 直接请求能返回完整 LRC。
- 处理：加载器改为 lyricPrefs()，从 prefsStore.get() 读当前偏好；单测 sandbox 只留 prefsStore、删掉 prefs，让同类错误直接失败。

## 34. 缓存只挂在 ended 上会导致交叉淡化切走的歌永不缓存。
- 原因：淡化时换牌后淡出方由 finishCrossfade 暂停，<audio> 不会派发 ended；而缓存写入只挂在 onEnded 上。单曲循环则是我们手动回到 0（没有原生 loop），每遍都会触发 ended，不需要单独处理。
- 现象：打开「缓存歌曲」后，正常播完的歌能进缓存，但交叉淡化切走的歌始终不缓存。
- 处理：beginCrossfadePlayback 记下淡出曲目（item/duration），finishCrossfade 在暂停鬼影前按 duration - currentTime <= 1.5s 判断它已到结尾并发 POST /online/played；淡化的 fade 被夹到 remaining - 0.05，所以正常淡化一定满足。

## 35. 波点成功态只认 success、取消不带 key 会导致扫码成功被判失败或新码被删。
- 原因：① 波点包的 login_qr_check 成功态是 confirmed（session 已写进仓库），插件只认 success，把它归成失败；② 取消登录只带 provider，Host 无条件删掉当前状态，刷新/关窗的取消请求晚到就会删掉新一次尝试；汽水的 error 状态还丢了 failure.case。
- 现象：波点音乐扫码后显示「平台拒绝了这次登录」；汽水音乐刷新二维码后显示「这次登录已经被新的尝试取代」，扫了也没反应。
- 处理：bodian 映射 confirmed → success 并取回 session、二维码 TTL 改为包本身的 5 分钟；取消改为按 key 归属（客户端带 key，state.cancel(key)/bridge/route 只释放对应尝试）；qishui 透传 failure.case。

## 36. 无条件调 forgetTokens 会导致退出登录时 Host 崩溃。
- 原因：/online/logout 对所有平台无条件调 omni.forgetTokens，波点原生源没有该方法 → 抛 unavailable 并从未捕获的路径逃出，Host 进程退出；退出瞬间 socket 已断时，500 兜底写回也可能再抛一次。
- 现象：播放中点「退出」，DSH 弹出「应用无法启动或已意外停止」，crash log 为 MusicError: Bodian Music does not support forgetTokens。
- 处理：波点补 forgetTokens / logout（清 session 与行缓存）；/online/logout 的 token 清理改为 best-effort；routes.js 的兜底 catch 再包一层，写不出去时直接销毁响应。

## 37. 删函数但轮询 effect 还在会导致面板每 3 秒报 ReferenceError。
- 原因：在线缓存对齐移除了缓存角标刷新函数，但 panel.js 里给「正在播放」歌曲轮询缓存状态的 useEffect 还在，定时器每 3 秒触发一次未定义引用。
- 现象：crash log 的 renderer 段出现 Uncaught ReferenceError: refreshCacheStatus is not defined，面板有红灯级报错。
- 处理：删除这段轮询（缓存角标已随方案移除）。

## 38. 原生源 toTrack 不带 provider 会导致封面与取流变成 undefined。
- 原因：onlineTrackOf 只读 result.provider，而原生源（qishui/bodian）的 toTrack 只带 sourceRef；客户端于是生成 online:undefined:<id>、cover?provider=undefined、stream?provider=undefined，Host 拒绝，媒体元素最后只报笼统的「no supported source」。
- 现象：汽水、波点的歌曲列表全部是占位图；点歌弹出 无法播放：Failed to load because no supported source was found.。
- 处理：两个源的行补 provider；onlineTrackOf 回退 result.onlineProvider 与 result.sourceRef.sourceId；客户端取流失败不再回退同一 URL 当媒体源，而是展示 Host 返回的真实原因。汽水封面还要按 Folia 追加 ~<template_prefix>-image.image（裸 /img/<uri> 会被抖音 CDN 400）。

## 39. 只认 singer 名或旧 card.cover 会导致歌手页/专辑卡缺图或缺 id。
- 原因：/online/artist-songs 需要 artistId，但客户端从历史/恢复队列拿到的行可能只有歌手名；而歌手页的专辑卡片渲染读的是 card.cover（旧集合形状），artist_albums 却只返回了 coverUrl；artist_detail 也未被使用。
- 现象：汽水歌手页报 Qishui singer has no id；波点歌手页的专辑卡片全是占位图，且没有歌手头像。
- 处理：两个源在 artistSongs 里用歌手名走一次自己的 search 解析 id（Folia 用歌曲里的 catalogRef，效果等价）；artist_albums 同时带 cover 与 coverUrl，artist_detail 提供头部信息；播放快照保留 artistsDetail/albumId。

## 40. 在线匹配写死 !onlineProvider 会导致在线歌曲点「在线匹配」无反应。
- 原因：matchOnline 与 openOnlineLyric 都写死了 !track.onlineProvider 才打开窗口；Folia 对在线歌曲用 OnlineSongLyricMatch，同样有匹配窗，只匹配歌词。
- 现象：播放本地文件时「在线匹配」能打开搜索/匹配窗，播放在线歌曲时点了没有任何反应。
- 处理：在线歌曲也打开同一个窗，传 online: true：隐藏封面/元数据/停止匹配开关，只保留歌词匹配；保存走 /lyrics/match-apply 的 online: 路径，写入 online:<provider>:<id> 歌词记录，不写文件标签。

## 41. 头像/资料只读单一字段会导致登录后无头像或出现重复表单。
- 原因：① QQ 的会话 cookie 只有 qqmusic_session，没有 uin，旧逻辑取不到头像；② 酷狗 Lite 的 user_verify 经常返回空昵称/头像，但同账号的酷狗完整会话有；③ 波点的 login_status 返回用户对象本身，适配器只读 .user，刷新时拿不到资料；④ /online/providers 只要 account.user 是空对象就跳过 profile；⑤ Folia 把 Navidrome 这种服务器连接放在设置里，登录窗只服务扫码平台，我们两处都做了一遍。
- 现象：登录窗平台列表只有 logo；QQ、酷狗、波点登录后账号页没有头像。Navidrome 同时存在设置页表单和登录窗口表单。
- 处理：QQ 用 session.userid 生成 qlogo；酷狗 Lite 在没有头像时回退同账号酷狗资料；波点 readUser 兼容两种形状并映射头像字段；账号读取按字段合并，不用空值覆盖；登录窗有头像时显示头像；Navidrome 的单一表单归位到设置 → 在线，删除独立对话框与登录窗分支。

## 42. settings.js 引用 player-sheet 内部函数会导致切到歌词/数据页白屏。
- 原因：这两个标签用到的 mpSmallButton、mpSegment 只在 player-sheet.js 的组件函数内部定义；settings.js 在另一个组件里调用同名全局，实际是未定义引用，渲染一进入该标签就抛 ReferenceError。
- 现象：设置弹层里点「歌词」或「数据」，插件面板直接空白（React 渲染抛错）。
- 处理：把两个小控件抽到 primitives.js 作为共享顶层函数（player-sheet 内部同名局部函数会自然遮蔽原实现），settings 直接复用；新增「所有设置标签都能渲染」的回归测试。

## 43. 把 Audioid 当 albumAudioId 会导致酷狗点 A 播 B。
- 原因：旧 normalizeSong 把 Audioid / audio_id 当 albumAudioId，概念版还把 mixsongid 当 albumAudioId；package/legacy 的 song_url 带着错误 ID 请求，解析到别的文件。
- 现象：搜索结果点一首歌，实际播放另一首不相干的歌。
- 处理：只从 album_audio_id / albumAudioId 取专辑音频 ID；package 每档 metadata → hash-only 回落；网关/v6 兜底保持 hash-only；测试断言参数顺序。

## 44. mute 用默认 ramp 重写 master gain 会导致 TTS 避让渐变被取消。
- 原因：applyOutputVolume 先 setVolume(target, fade)，紧接着 setMuted(muted) 用默认 15ms ramp 再写一次 master gain，把长渐变取消；mute 状态没变时也会重写。
- 现象：避让设为 300ms，实际音量瞬间跳变，听不到渐变。
- 处理：foliaGraph.setMuted 接受 rampSeconds；player 调 setVolume 与 setMuted 时传同一个 fade。

## 45. 概念版只发半套 metadata 会导致 high/lossless 取流 502。
- 原因：0.38 的精确身份改造让歌单/专辑行只剩 album_id、album_audio_id 为 0，却仍先发半套 metadata；接口回了一个别的文件的地址。同时标准路径的循环固定从 flac 开始、使用 hqHash/sqHash，和 Folia 的“请求档位 + 主 hash”不一致。
- 现象：0.38.0 播放酷狗概念版的任意歌曲，high / lossless 的 CDN 地址返回 404，Host 回 502；standard 仍可播放。
- 处理：只在 album_audio_id 存在时发 metadata，否则直接 hash-only；嵌套 package 归一化保留 album_audio_id；标准路径按请求档位的 Folia 阶梯（128 / 320 / flac）并使用主 hash；Host 在已解析地址仍 404 时按 Folia 阶梯降一档再取。

## 46. 桥接层不补 buildTimedWords 会导致云阶/心象英文歌空白。
- 原因：这两个样式按 line.words 建列/落点；行级 LRC 或在线歌词回退只有 fullText 时，legacy 桥接生成 words: []，布局为空。中文/日文常见逐字词轴，所以不触发；Folia 的解析器总会用 buildTimedWords 合成词轴，本插件没有在桥接层补齐。
- 现象：云阶（partita）和心象（cadenza）在英文歌里没有任何字形/布局，其他歌词样式正常。
- 处理：legacyLinesToFolia 对空 words 调用 FOLIA_PENDOLO 的 buildTimedWords；foliaStyleLines 在舞台入口再做一次空 words 修补。

## 47. 新引擎不读回 prefs.volume 会导致重启音量回到 100%。
- 原因：player.js 的初始 state 把 volume 固定为 1；setVolume 会写 prefs.volume，但新引擎创建时没有读回。
- 现象：音量滑杆保存后，退出并重新打开 DSH 又回到默认值。
- 处理：创建播放引擎时从 prefs.volume 恢复并 clamp 到 0–1；无效值回退 1。

## 48. 把单页 limit 当总数会导致 QQ 歌单只显示 100 首。
- 原因：/user/playlist-detail 是分页接口，单页上限 100；旧代码只发一次 offset=0, limit=1000，把第一页当完整歌单。公开歌单走匿名接口不受影响。
- 现象：QQ 歌单总数正确（例如 211），但歌曲只有 100 首。
- 处理：按 Folia 的页模型每页 100 首，累计 offset，直到 total、空页或重复页；同时按 dirName 区分自建与收藏，收藏走匿名完整路径。

## 49. 时钟用 DOM querySelector 找 audio 会导致淡化后歌词冻在首字。
- 原因：共享时钟用 document.querySelector('audio.mp-audio-host')，查到的是文档里的旧 A deck；active deck 已切到 B，旧 A 在 finishCrossfade 里被 removeAttribute('src') + load()，时间归 0。行索引来自 active deck，时钟却停在 0。
- 现象：播放一段时间、发生切歌淡入淡出后打开播放页，所有 Folia 歌词样式的逐字/逐词动画停在每句第一个字，行索引仍会跳下一句。
- 处理：播放器暴露 getPlaybackTime() / getActiveAudio()；Folia 样式、Pendolo、音频带全部读 active deck。Folia 也是如此：共享 lyric clock 来自 active transport。

## 50. 行索引用 4Hz timeupdate、词动画用 60Hz 会导致逐词错位。
- 原因：Folia 舞台的 currentTime 是约 60Hz 的 rAF 时钟，但当前行索引来自父层 usePlayerTime() 的 timeupdate（约 4Hz）。两个时钟在行边界最多错开约 250ms，逐词动画和行索引不同步。
- 现象：逐词扫色/高亮和实际进度有偏差，行切换时尤其明显；Folia 同一首歌、同一词源正常。
- 处理：在 FoliaStyleStage 内用同一 clock 逐帧计算 foliaLineIndex（与 Folia 的 findLatestActiveLineIndex 一致，行间间隙返回 -1），不再依赖父层 active。

## 51. override 只存 LRC 却保留 wordLevel 会导致面板说有词轴实际没有。
- 原因：旧版本的 override 记录只持久化了 LRC，词轴/raw 没有写进 payload；匹配记录仍保留 wordLevel 标记，造成“知道有词轴，实际没有词轴”。
- 现象：酷狗/QQ 源有逐词歌词，但云阶、心象空白或逐词不准；/online/lyric 返回 lines:null、raw:null、wordLevel:false，而 state.matched.wordLevel:true。
- 处理：/online/lyric 检测 matched.wordLevel===true 且 payload 无 words 时，用匹配来源重新取一次并写回 lines/raw/wordLevel；同时在线匹配获取歌词时带上来源 cookie/session。

## 52. providers 把 local 当在线源且异步追加会导致重复「本地音乐」和列表不全。
- 原因：/online/providers 把注册表里的 local 也当作在线来源返回，客户端 p3SourceList() 先固定加 local，再由 provider map 追加一次；provider map 初始为空，来源菜单按异步结果逐项增长。
- 现象：左上角来源菜单有两个「本地音乐」；第一次打开时只有部分平台，过一会才补全。
- 处理：Host 只返回 kind === 'online' 的来源；客户端跳过 local，并在 providersPhase 不是 ready 时为已知平台渲染禁用占位项（状态「加载中」），加载完成后原位替换。

## 53. 歌手行 truncate 无显式行高会导致莫奈歌手名上下被裁。
- 原因：Monet 的歌手行使用 truncate（overflow:hidden）且没有显式行高；Folia 全局由 Tailwind preflight 提供 line-height:1.5，本插件宿主的继承行高更紧，斜体字形超出行盒后被裁。
- 现象：Monet 样式左上角歌手名（如「伍佰 & China Blue」）顶部/底部被裁掉一截，标题和其他样式正常。
- 处理：VisualizerShell 显式设置 Folia 的 line-height:1.5，恢复 Folia 的全局排版上下文；Monet 源码保持与上游一致。

## 54. 自写样式顺序并漏掉行高会导致列表顺序与排版偏离 Folia。
- 原因：13 个样式目录虽与上游一致，但本地 FOLIA_STYLE_META 使用了另一套 order；VisualizerShell 移植时漏了 Folia 的 1.5 行高和 flex 居中。
- 现象：样式选择器顺序与 Folia 不同；部分样式的全局排版上下文也有偏差。
- 处理：按各 entry.tsx 的 order 重排（sonnet 10…still 130），shell 恢复 line-height 1.5、flex column 居中。

## 55. grid stretch 加无 min-width 会导致账号卡被撑高、长 ID 溢出。
- 原因：CSS grid 默认 align-items:stretch，同一行高度取最高的 Navidrome 表单；账号 ID 在 flex 子项中 white-space:nowrap 且没有 min-width:0/省略规则。
- 现象：酷狗卡片和 Navidrome 并排时被拉高；汽水音乐的长 ID 横向溢出卡片。
- 处理：所有账号卡片设统一 min-height；Navidrome 表单默认收起，展开时 grid-column:1/-1 独占整行；mp-online-id/mp-online-nick 加 min-width:0 + ellipsis，并补 title。

## 56. 缺旧版 getSongInfo 回退会导致酷狗个别老歌 404。
- 原因：这些曲目的 search 行没有专辑身份（album / albumId 为空），现代 /song/url 返回的是已从 CDN 消失的旧对象地址；hash 本身仍有效。Folia 的酷狗 provider 在取不到/失效时会走旧版 m.kugou.com/app/i/getSongInfo.php?cmd=playInfo，本插件原先没有这层回退。
- 现象：酷狗概念版播放某些老单曲提示「无法播放：HTTP 404」，同队列其他歌正常。
- 处理：resolveLegacyStream(hash) 取旧版接口的 url/backup_url；/online/stream 在酷狗 CDN 404 时先尝试 legacy URL，成功才递归代理，失败继续原质量降级。

## 57. 字幕底距 shim 写死 64 会导致底部字幕比 Folia 低。
- 原因：usePlayerSubtitleBottomPx 是宿主边界桩，固定返回 64；Folia 桌面档是 32px 基线 + 80px 净空 = 112px。字幕组件源码本身与上游一致。
- 现象：底部翻译字幕离底边比 Folia 近，控制条与字幕的呼吸感不同。
- 处理：边界 hook 恢复 112px；chrome 隐藏时退回 32px 基线；底部字幕组件、行解析、active/recent/upcoming 逻辑不改。

## 58. 能力表写 false 且未实现写接口会导致酷狗概念版/波点不能点赞。
- 原因：来源能力表把 kugouLite.likeWrite 写成 false，且 setOnlineLiked 对概念版直接抛错；波点 source 没有声明 likes / likeWrite，也没有实现 likedIds / setLiked。
- 现象：播放页点喜欢只看到「暂不支持」；酷狗概念版和波点都无法取消/写入喜欢。
- 处理：概念版通过 cloudlist 的 playlist_tracks_add / playlist_tracks_del 写内置「我喜欢」；波点补 liked_songs 与 like_song。酷狗取消时按 hash 在「我喜欢」歌单里解析 fileid，不把其他歌单的行号传过去。

## 60. 一次性自绘列表不走上层组件会导致加入歌单弹窗不像 DSH。
- 原因：online-add-to-playlist-dialog.js 早期直接写了一次性行布局，没有走主题规范要求的组件/样式层级。
- 现象：弹窗每行是裸按钮，自己写边框、背景、10px 圆角和错误色，和其他设置弹窗不一致。
- 处理：改为 SetRow + Button，容器用 .mp-set-card，加载/空态用 .mp-folder-state，错误用 .mp-online-error；标题改用「添加到歌单」，页脚用 Button ghost。

## 61. 来源页写死「本地」不按曲目分支会导致在线歌也显示本地与译文开关。
- 原因：player-sheet.js 的来源页是自定义实现，标签固定为「本地」，facts 和歌词来源选项没有按曲目类型分支。
- 现象：在线歌曲仍显示「本地」标签和「在线曲目，没有本地文件」；来源页混入翻译开关、歌词分词、在线文件大小/时长，和 Folia 的信息层级不一致。
- 处理：标签按 local/online/navidrome 动态化；在线不显示本地 facts，本地只保留文件名与大小/码率，Navidrome 显示 Song ID；纯音乐只作为无源状态标签；偏移支持直接输入；翻译开关与分词从来源页移回控制/音质页。

## 62. 改旧壳 PlayerPage 而不是 NowPlaying 会导致底栏改了没变化。
- 原因：仓里有两套播放页外壳；p3-shell.js 只挂载 NowPlaying，PlayerPage 是已经不再挂载的旧壳。没有先确认挂载点就按文件名改了“看起来最像”的底栏。旧壳、旧测试和 .mp-page-* 样式随后已删除。
- 现象：改的是 player-page.js 的 .mp-page-pill，但当前全屏播放页实际挂载的是 now-playing/index.js 的 NowPlayingCapsule，界面上没有任何变化。
- 处理：改 NowPlayingCapsule：循环键按 Folia 的 off → all → one 三态调用 player.setLoop，不再用会改随机顺序的 cyclePlayMode；胶囊颜色改用 --dsw-alias-* token。队列作为插件额外入口保留。

## 63. 只按单曲查 liked、不调 liked-ids 会导致红心一直不亮。
- 原因：likeStateOf 从 onlineStore.liked[track.path] 取状态，但客户端只在右键菜单里按单曲请求 /online/liked，从未调用已有的 /online/liked-ids；onlineStore.liked 初始化为 {} 后一直为空。不是歌单、不是 UI 图标，也不是 favoriteSet 的问题。
- 现象：同一首在线歌曲在 Folia 中红心点亮，本插件显示空心；歌手、封面和点击后的写入都正常。
- 处理：loadProviders() 在来源列表返回后，对每个 loggedIn 的来源调用 loadLikedIds，按 online:<provider>: 前缀替换该来源的键，再合并进全局 map；Host 已返回完整 track.path，客户端也兼容裸 id。

## 64. 只取歌单第一页会导致网易云等平台的歌曲数被单页上限截断。
- 原因：Host 的 playlistSongs 只请求第一页，把单页 limit/pagesize 当成了总数。Folia 的 provider 接口是 getPlaylistTracks(id, limit, offset)，UI 按页继续请求。
- 现象：某些平台的歌单只显示固定数量：网易云 1000、波点 100、汽水 60、酷狗标准版 300、酷狗概念版 2000/4000。
- 处理：网易云按 trackCount 以 500 首循环；波点按 100 首、汽水按 60 首并用 hasMore、酷狗标准版按 300 首、概念版按 100/200 首继续翻页，直到 total、hasMore 结束或短页。QQ 自建/喜欢已有分页，Navidrome/本地无固定上限。

## 65. 样式 seed 用 trackPath 而非 displaySong.id 会导致花火/绘光竖排。
- 原因：两个样式的源码与 Folia 逐字节一致，但 visualizerGeometrySeed 传错了。Folia 用 displaySong.id（App.tsx），本插件用完整 trackPath；在线歌曲因此是 online:provider:id，所有按 seed 决定的 shot/layout 分支都跟着变，其中包含竖排 variant。
- 现象：同一首歌词在花火或绘光里偶尔排成竖列，Folia 参考实现是横排；切换歌词/重新播放时又会变。
- 处理：NowPlaying 统一用在线 onlineId、本地 id / path 生成 visualizerSeed，同时传给背景、样式解析和 LyricStage；不要再传 track.path。

## 66. 只抄常量、缺 profile 五级来源与 blend hold 会导致增益结果与 Folia 不同。
- 原因：本地只实现了 file/played/tag/live/typical 五级来源；缺少 profile/head/platform，typical 不去重，实时 meter 用本地简化记录，文件缓存的是最终 gain，播放中也没有 blend hold。
- 现象：目标 -14 LUFS、+6 dB 等常量与 Folia 相同，但同一首歌的 dB 和播放中移动仍可能不同。
- 处理：生产规则直接使用 MPAudio.chooseBalance / planBalanceMove / whyNotWholePlay；记录改为 file/played 的 loudness+peak，typical 按歌曲 key 去重；文件分析改用 22.05kHz + Folia K-weighting/gated loudness；播放中按规则 ramp/hold。

## 67. 平台增益只放响应头、不存缓存元数据会导致缓存重播丢失增益。
- 原因：平台增益只在 /online/stream 解析 CDN 地址时存在，媒体缓存的文件元数据没有保存 replayGain；缓存命中路径直接读文件，没有 header。
- 现象：首次解析在线播放地址时平衡能用平台增益，缓存音频重播又退回 typical/live。
- 处理：当前先通过 stream 响应头传 x-music-track-gain/peak；后续应把增益写入媒体缓存元数据，在缓存命中时恢复。

## 68. 把 profile 当字段对齐且无下一首预取/头部分析会导致平衡不准。
- 原因：播放器只能测量已经取到的当前曲 blob；没有下一首预取，也没有 partial head。
- 现象：本插件已有 music.profile.v1，但 Folia 的 automix profile 是独立预分析服务，会分析当前和下一首，并为 Navidrome 只读头部。
- 处理：当前只把真实测出的整曲 programLoudness/peak/leadIn 作为 profile；没有下一首或头部数据时传 null。

## 69. 缓存命中绕过平台增益头会导致重播 gain 变 null。
- 原因：replayGain 原先只存在于 /online/stream 的 fresh 分支，缓存元数据没有保存。
- 现象：首次解析在线流时 platformDb 有值，之后命中媒体缓存又变回 null。
- 处理：mediaCache.store 持久化四个数值增益字段，serveCachedAudio 重新写 x-music-*-gain/peak 响应头；/online/replaygain 也先查缓存。

## 70. 对 Navidrome 下一首整曲下载做 profile 会导致浪费带宽。
- 原因：Folia 对 library server 只读文件头部；整曲分析属于本地文件或已缓存音频。
- 现象：profile 调度直接把 Navidrome 下一首当本地曲整曲下载，浪费带宽。
- 处理：对 Navidrome 用 Range: bytes=0-1572863 取前缀，解码成功才写 partial: true 的 profile；失败不重试、不占播放。

## 71. profile 写入只重建四个字段会导致其余分析结果被丢掉。
- 原因：profile 存储写入时重新构造了四个字段，而不是保存分析结果。
- 现象：profile.js 原来只存 programLoudness/peak/leadIn/partial，接上 Folia trackProfile 后其它字段被丢掉。
- 处理：noteProfile 现在保存完整 profile 对象；profileFor 返回完整对象，平衡只取自己需要的字段。

## 72. 用 Blob Worker + IIFE bundle 却不保证独立加载会导致 Worker 起不来。
- 原因：bundle 是 IIFE 函数而不是模块；直接 import 不可用，且 Worker 里没有主线程的全局变量。
- 现象：用 __mpProfileBundle.toString() 构造 Blob Worker，主线程和 Worker 都要能独立加载分析代码。
- 处理：Worker 代码内重新调用 __mpProfileBundle()；创建/运行失败时回退主线程分析，播放不被阻塞。

## 73. 把 gridFromBeats 当模型推理会导致没有 Beat This 时仍走频谱估算。
- 原因：模型推理在 Electron/GPU 侧，插件没有权重和桥；gridFromBeats 只负责把已有拍点折成均匀网格。
- 现象：gridFromBeats 已能生成 bpm/downbeat，但没有 Beat This 模型时 profile 仍然走 Folia 的频谱估算。
- 处理：把 gridFromBeats 暴露给未来的模型调用方；没有 grid 时不要伪造拍点，让 analyseTrack 走 fallback。

## 74. 存储 profile 不做版本校验会导致旧分析结果被当有效。
- 原因：存储对象没有版本校验，字段齐全就被当成有效。
- 现象：分析字段/算法升级后，旧 music.profile.v1 仍被平衡读取，结果和当前 trackProfile 不一致。
- 处理：完整 profile 带 TRACK_PROFILE_VERSION；profileFor 在版本存在且不匹配时返回 null，让 analyseTrack 重新生成。

## 75. 消费端不读 profile 的拍点相位会导致过渡不卡拍。
- 原因：消费端没有把 profile 的拍点相位换算成 incoming 的下一拍时间。
- 现象：profile 已存 bpm/beatOffset，planBlendShape 仍传 nextBeatIn: null，过渡没有卡拍。
- 处理：prepareCrossfade 用 bpm/beatOffset 计算 nextBeatIn，把 planBlendShape 的 overlap 写回计划。

## 76. 未缓存时 fetch 在线 stream 做分析会导致整首下载。
- 原因：streamUrl 在缓存 miss 时会解析 CDN 并代理，不是本地读取。
- 现象：为了尽早给在线下一首做 profile，直接 fetch 它的 stream URL，会在未缓存时触发整首下载。
- 处理：先请求 /online/cache-info；只有 cached: true 才读 streamUrl，否则等跨淡预取 blob 或跳过。

## 77. 把 keyRelation 当移调会导致和声被破坏的误解。
- 原因：Folia 的 key 规则是不给冲突和声时间（缩短 overlap），不是移调；移调需要真实 pitch shift，会毁掉整段混音。
- 现象：crossfade 读了 keyRelation 就以为做了调性匹配。
- 处理：只按 Folia 的 LENGTH_SCALE 缩放 overlap；不把 key 写进 pitch/gain。

## 78. planner 的 hold/together 未被 transport 消费会导致听感仍是纯 crossfade。
- 原因：planner 只给了计划，执行端没有消费 hold/together/crossover。
- 现象：chooseTransitionStyle 选出了 bassSwap/tailRide，crossfade 仍传 hold: 0, together: 0，听感还是纯 crossfade。
- 处理：prepareCrossfade 把 shapeBlend 结果写进 xfadePrepared，beginCrossfadePlayback 传给 crossfadeTo；beatCut 允许 0.02 秒级窗口。

## 79. profile 分析绑在 normalizeVolume 上会导致关平衡后失去 bpm/key。
- 原因：profile 消费端是 automix，不是音量平衡；两者只是共享测量结果。
- 现象：关闭智能平衡后 crossfade 也没有 bpm/key/sections，因为 profile 分析被 normalizeVolume 提前 return 掉了。
- 处理：关闭平衡时仍异步分析 profile，但立即 finish()，不阻塞播放；分析完成后再调度下一首。

## 80. 首音前等整首 blob 与分析会导致在线播放长时间加载。
- 原因：fetch(...).blob() 等完整响应，然后解码整首、跑 profile，playAfterLoudness 等分析结束才 play()；平台/网络不是根因。
- 现象：同一首在线歌，Folia 很快出声，本插件长时间停在加载。
- 处理：在线当前曲直接 audio.src = Host /online/stream，立即 resolve 播放门；profile 只在媒体缓存命中时后台补，平台增益后台 HEAD 取。

## 81. 用 200 响应代替 206 会导致拖动进度回到开头。
- 原因：媒体元素 seek 会发 Range 请求；CDN/Host 若回 200 而不是 206，Chromium 把它当不可 seek 流，重置到 0。旧 blob 方案通过本地随机访问绕开了它。
- 现象：在线歌曲拖到中间又跳回开头；首音正常。
- 处理：Host 缓存已解析 CDN URL，Range 请求复用同一对象；CDN 对 bytes=0- 回 200 时直接标记为完整 206，对后续 start>0 的 Range 读取全量并切片为 206 + Content-Range；preload=auto 让浏览器提前缓冲。

## 82. 代理流的 seekability 不等价于 CDN 会导致 seek 重置。
- 原因：媒体元素播放的是 Host 代理 URL，Chromium 对代理资源的 seekability 判断不等价于 CDN 原生资源；旧 blob 能 seek 是因为本地随机访问。
- 现象：Host 已返回 206/Content-Range、固定 CDN URL、preload=auto，在线 seek 仍回开头。
- 处理：当前曲改用 MediaSource，Host 字节流 append 到 SourceBuffer，seek 由客户端 buffered ranges 决定；不支持 MSE 的格式回退直连。

## 83. 用 MSE 已 append 的 duration 当总长会导致进度条越拖越短。
- 原因：MSE 的 audio.duration 只覆盖已经 append 的媒体，不是整首；seek bar 用它当最大值，90% 实际是“已加载前缀的 90%”，随后又被 api.seek clamp 到该前缀。
- 现象：总时长显示 0/1:38 时拖到 90%，加载完整后却停在不到一半。
- 处理：UI 使用 max(media duration, 歌曲已知 durationSec)；sourceopen 时把 MediaSource.duration 设为整首时长；api.seek 对 MSE 使用已知整首时长作为上限。

## 84. 泛型 octet-stream 会导致 isTypeSupported 失败并静默回退。
- 原因：CDN 返回 application/octet-stream，MediaSource.isTypeSupported 为 false，playOnlineMse 回退 playOnlineDirect；Host 又把泛类型原样转给浏览器。
- 现象：MediaSource 代码已接，但拖动仍回开头；实际走的是直连回退。
- 处理：Host 按 CDN URL 扩展名/音质归一音频 MIME；MSE 只对真正的 audio/* 类型启用，泛类型不再直接判失败。

## 85. profile 精确锁旧版本会导致启动时覆盖 install-local 的副本。
- 原因：profile 的 package.json 把 dsh-music-panel 锁成 0.38.0；DSH 启动时 pnpm 从 store 恢复这个精确版本，覆盖刚复制进去的 profile 副本。
- 现象：install-local 显示复制成功，完全重启后设置页又显示 0.38.0，client.js 还是旧版。
- 处理：开发期把依赖改成 link:D:/.../dsh-music，让 profile 指向工作区；install-local 遇到 junction 直接拒绝，避免 rm(src) 穿透链接删掉仓库。

## 86. 在 play 事件就置 playing 会导致未出声却显示暂停图标。
- 原因：UI 的 state.playing 在媒体 play 事件就置 true；MSE 等待 buffered 时调用 audio.play()，play 先于真正出声的 playing 到达。
- 现象：在线曲跳到未缓冲位置后，底栏还显示暂停图标，但实际在等待缓冲、没有声音。
- 处理：playing 事件才置 state.playing=true；play 只保留预取等副作用；pending seek 立即置暂停态。

## 87. 用普通 LRC 存逐字歌词会导致重播只剩逐行。
- 原因：普通 LRC 没有 <mm:ss.xxx> 词时间；平台的 YRC/QRC/KRC 原始格式又不适合直接塞进标签。
- 现象：把在线逐字歌词按普通 LRC 写入 USLT/LYRICS，重播后只剩逐行。
- 处理：先用 Folia serializeEnhancedLrc 把 lines[].words[] 写成增强型 LRC，再写 MP3 USLT / FLAC LYRICS；本地 loader 会自动识别 enhanced-lrc。

## 88. 直调酷狗包不补 userid/token/cookie 会导致云盘全空。
- 原因：酷狗 user_cloud 由 kugoumusicapi 在本地签名，包本身不记得登录态——Folia 靠桥接层（electron/kugou/kugouApiBridge.cjs 的 invokeModule）给每次调用补 userid/token/cookie，本插件直接调包时漏了这三个，上游回 error_code 20010（param error），被当成空列表…
- 现象：在线页切到「云盘」，四个平台全部显示「云盘为空」；账号登录着，平台客户端里也确实有文件（截图里酷狗 VIP 已登录）。
- 处理：cloudSongs 补 token + kugouCookies()，未登录直接 []，有 error_code 就抛错；normalizeSong 的 hashKey 以 hash 兜底；normalizePackageSong 的扁平行判定只看 base/audio_info；云盘标题去掉容器后缀；客户端空态按 p3SourceLoggedIn 换文案。

## 89. 单节点 CDN 403 且无多节点重试会导致海外网易云播不出。
- 原因：平台给 /song/url/v1 签的是某一个 CDN 节点的地址，节点会因为请求来源 IP 拒绝（403），文件本身没问题；而路由只给酷狗的 404 写了重试，别的平台直接 fail(502,'UPSTREAM_FAILED','HTTP 403')。更关键的是客户端：非 2xx 只拿到状态码就降级 startOnlineDirect()，把同一个 502 地址塞进媒体元素，Chromium 把 JSON 错误页当音频，于是 Host 写好的 error.message 被内核文案顶掉。
- 现象：海外网络点播网易云稳定失败，toast 是 PipelineStatus::DEMUXER_ERROR_COULD_NOT_OPEN: MediaSource endOfStream…；同一首歌手工换成另一个 CDN 节点就能播（issue #26）。
- 处理：路由对 403/404/408/429/5xx 先删缓存重新要一次签名地址（换节点），仍失败再降一档音质，最终把状态码写进文案并带 upstreamStatus；客户端先读 error.message 走 onError 并停下、不降级直连；onError 把浏览器 pipeline 文案换成 page.playbackFailedMedia 且只留在日志。

## 90. 消费端只在 P3Shell 会导致面板折叠后 music_control 全部积压。
- 原因：Host 侧是「拉取式」队列（/music/control/pending，读即清空、上限 10、无过期），而唯一的消费端（2 秒一次 setInterval）写在 P3Shell 里，P3Shell 只挂在 main 槽——折叠即卸载，消费能力被绑在「面板可见性」上。另有两处连带缺陷：本地 play 依赖的曲库同样只在面板挂载时加载；多窗口下 player.play() 只在领导者窗口出声，消费者必须与领导者一致。
- 现象：音乐面板折叠到 dock（或从没打开过）时，music_control 的播放/暂停/切歌全部积压，工具却返回 queued: true；一展开面板，最多 10 条指令一次性连续执行。
- 处理：新增 services/player/control-drainer.js，由 apply() 的 ctx.effect 启动（立即首拍 1s、之后 2s、visibilitychange 补拍、定时器 unref 以免测试进程被挂住）；删除 P3Shell 原有轮询；applyControlAction 改成可 await，本地播放前 ensureLibraryLoaded()；消费者先判 player.isLeader()；超过 5 分钟的指令丢弃并记日志。

## 91. 字号/间距只写 CSS 钩子不接渲染器会导致设置拖动无变化。
- 原因：这四项是上一代经典 DOM 歌词列表的产物，只写 CSS 钩子（--mp-lyric-size / --mp-line-gap / mp-align-* / is-blur）。经典样式移除时（第 27 条）只迁移了 lyricStyle，mpTextLines 不再被任何渲染器调用、也不在 manifest 里，全仓唯一产出 .mp-np-line 标记的是样式包加载失败时的兜底；Folia 样式的排版契约只有 lyricsFontScale / subtitleFontScale 等无量纲输入，没有 px 字号与行距；时计宿主还把这三个值写死成 1。
- 现象：设置 → 歌词拖动「字体大小」「歌词间距」毫无变化；「模糊非当前歌词」「歌词对齐方式」同样无感；翻译缩放在时计样式上也不生效。
- 处理：「字体大小」改绑 lyricsFontScale（70%–150%），「翻译字体缩放」统一 50%–150%；删掉间距 / 模糊 / 对齐三行与 text-styles.js、lyrics-scroll.js、--mp-lyric-* / mp-align-* / is-blur / mp-np-line-trans 等死钩子；prefs.js 读取时丢弃旧键；时计改读真实 prefs；莫奈 / 静止下的「字幕背景」置灰并说明。

## 92. 用归一化后的 source 判断平台歌词会导致择优开关永不生效。
- 原因：loadOnline 把 source 归一成 'online' | 'imported'（来源页要的是这两个词），它不再等于 track.onlineProvider；拿 result.source === track.onlineProvider 判断「这是平台自己的歌词」永远为假。
- 现象：Folia 的 keepProviderWordTiming 接上后从不生效；平台自带逐字歌词仍被其他来源覆盖。
- 处理：loadOnline 另记 ownPlatform = source !== 'imported' && override !== true，maybeUpgrade 用它判断；/online/best-lyric 增加 only（只查首选来源）与 requireWordLevel（行级结果不写回）。

## 93. i18n 同一键两处定义且只改一处会导致显示旧文案。
- 原因：settings.tabPlayback 在 i18n.js 与 strings.js 各定义一次，合并顺序决定最终显示；只改其中一份，另一份会把值覆盖回去。
- 现象：把「播放与音频」改成「播放控制」后，页签与标题仍有一处是旧名。
- 处理：两份字典一起改（中英共四处），页标题 v2.playback 同步改名；新增设置标签前先 rg 同名键。

## 94. 设置应用点挂在会卸载的 UI 上会导致折叠后定时器/增益失效。
- 原因：计时器写在 P3Shell 的 useEffect，标签增益的应用写在 NowPlaying 的 useEffect；P3Shell 只挂在 main 槽（折叠即卸载，见第 90 条），而播放器与音频元素活在 shell.overlay，音乐继续播、设置的应用点却没了。
- 现象：睡眠定时设好后把面板收进 dock，到点不暂停；ReplayGain 选单曲/专辑时，关掉面板后下一首仍沿用上一首的增益。
- 处理：睡眠定时按 Folia 的 useSleepTimer 逻辑移进插件 apply 生命周期；ReplayGain 按 Folia 的 calculateReplayGain 移到播放器 load()（本地 / Navidrome 取标签，其他在线无标签按原音量），面板只读显示。

## 95. 按 Content-Type 而不是字节解封装会导致 FLAC 被当 MP3。
- 原因：Host 的 onlineAudioMime 只要上游是 audio/* 就原样透传；客户端 MediaSource.isTypeSupported('audio/mpeg') 为真，于是把 FLAC 字节 append 进 MP3 SourceBuffer。Folia 不做这层代理/MSE，它把 URL 交给媒体元素，Chromium 自己按字节嗅探容器，所以没有这个失败。
- 现象：海外（荷兰）网易云无损 / 高解析档一播放就报「音频无法解码，取流地址可能已失效」；标准 / 较高档正常。CDN 返回 200/206、内容是合法 fLaC，但 Content-Type 是 audio/mpeg。
- 处理：Host 在写响应头前读取首个 chunk 嗅探容器（sniffAudioMime），实时流与媒体缓存副本都优先用嗅探结果；只在请求起点为 0（无 Range 或 bytes=0-）时嗅探。客户端保留 MSE 的 seek 能力，但在 MSE 解码失败时按 Folia 的直连路径回退一次。

## 96. 清空只删持久层不清内存会导致播放后旧数据复活。
- 原因：这些模块各自在内存里留了一份 cache；只删 localStorage 的键不会清内存，下一次写入把旧内容整份刷回持久层。歌词偏移还有一层由 lyrics.bundle 持有的 Map。
- 现象：设置 → 存储与备份里清空「分析数据 / 智能平衡数据 / 歌词」，数字变 0；播放一首歌后旧记录又出现。
- 处理：每类提供同时清内存与键的 clearProfileStore / clearBalanceStore / clearLyricClientCaches；偏移记忆在 lyricOffsetMemory.ts 增加 clearLyricOffsets 并用 build-lyrics 重建 bundle。设置页的清除按钮调用这些函数，而不是直接删键。

## 97. legacy 响度修正与 Folia 增益相乘会导致切模式声音反而变小。
- 原因：legacy 的 normalizeVolume / normalizeBase（响度修正）与 Folia 的 replayGainFactor（标签增益）是两个变量，写进同一个 deck 节点前相乘；两个入口各改其中一个，播放页还只写 prefs、不通知播放器。
- 现象：播放页把音频增益从「智能平衡」切到「单曲」声音反而更小，切到「关闭」也还在做响度平衡；设置页切同一个模式却基本正常。
- 处理：按 Folia 收敛成一个开关 replayGainMode 与一个写入函数 writeDeckGain：auto 只走 balance，track / album 只走 calculateReplayGain，off 是 0 dB；播放器订阅 prefs 里的模式，任何入口改完立即重算当前曲；normalizeVolume 只留作旧版镜像。

## 98. 面板另走本地标签查询、不记在线增益会导致总显示没有标签。
- 原因：酷狗这类平台没有文件标签，增益是播放地址应答里的 volume / volume_peak，Host 已把它放进 /online/stream 的 x-music-*-gain 头；但客户端只让播放器读了这个头，面板另开了一条只查本地文件标签的显示路径，且对在线歌曲直接跳过。增益没有「属于这首歌」的记录。
- 现象：同一首酷狗歌，Folia 的音频增益显示「单曲 -8.9 dB」，本插件显示「该文件没有增益标签」，单曲模式也不压。
- 处理：按 Folia 的 song.replayGain 建按曲记录 gainRecords（标签 / Navidrome / 平台头 / Host 缓存都写它），引擎与面板读同一份；在线歌曲也会问 /online/replaygain 作为持久兜底，响应头到达后覆盖。

## 99. 热替换只换 UI 不换播放器单例会导致增益显示未检测到。
- 原因：插件主机把新的 client.js 热替换进正在运行的页面，UI 是新的，window.__dshMusicPlayer 却是旧 bundle 建的对象；新面板读 gainAppliedDb / gainTags 得到 undefined，于是「未检测到」。
- 现象：更新插件后页面里已经是新文案，但音频增益三个模式都写「未检测到 ReplayGain」，重启一次也一样。
- 处理：createPlayer 增加引擎握手（必需方法 + 快照字段），不匹配就 location.reload() 一次（sessionStorage 记录要求，避免循环）；智能平衡模式缺值时改显示通用说明，不再谎称没有标签。

## 100. 热替换后新旧 bundle 各持一套 prefsStore 会导致控件不动声音照变。
- 原因：插件热替换只是把新 bundle 再执行一遍，播放器单例还留在 window.__dshMusicPlayer（第 99 条只修了“方法缺失”）。新 bundle 有自己的 prefsStore，旧引擎写的是旧 bundle 的 prefsStore 与 localStorage，新面板永远收不到通知。
- 现象：音频效果窗口里拖滑杆，音效真的变了，但滑杆、数值、选中态都不动；几乎每个控件都这样。
- 处理：构建时把内容哈希写成 CLIENT_BUILD，播放器实例记 build；模块在同页第二次执行、发现 window.__dshMusicPlayer 已存在时，直接 location.reload() 一次（sessionStorage 按 build 记一次，防循环），让 UI 与引擎来自同一次加载。

## 101. 取歌单前先全量 getMyPlaylists 且无超时会导致首次打开一直转圈。
- 原因：Host 每取一页都要先 getMyPlaylists 找这个 id（概念版 1–2 次上游请求）；一次慢或被限流就回退到旧版整表读取（逐页拉），前端只有骨架屏、没有超时。
- 现象：打开某个酷狗歌单停在骨架屏；切到另一个歌单立刻好，再切回来原歌单也能开了。
- 处理：playlistSongsPage 先直接问分页接口（行里的 id 就是 playlist_track_all 要的 id），账号列表只留给收藏歌单与被拒 id；客户端给一页 20 秒上限，超时转为可重试的错误。

## 102. 译文尺寸=歌词字号×翻译比例会导致两个滑杆被读成重复功能。
- 原因：译文行渲染尺寸 = 歌词字号 × 翻译比例；两个乘数串联，调哪个都在放大同一行字，且译文只跟着自己的比例走，没有额外语义。
- 现象：播放卡片「歌词显示」里「翻译字体缩放」和「歌词字号」并排，用户读成重复功能。
- 处理：只留「歌词字号」；译文固定为 Folia 默认的 90%（subtitleFontScale: 0.9）。卡片、设置页、播放页编辑器的第二个滑杆一并删除，旧存储值在读取时丢弃。

## 103. 页头按单行歌名固定高度会导致两行标题压住封面。
- 原因：页头高度写死为 封面高 + 14 + 108px（按单行歌名算），歌名区却是 position:absolute; bottom:0；标题两行时内容约 142px，比预留多出的部分只能向上顶进封面。
- 现象：播放卡片里歌名过长换行后，第一行文字压到封面下沿。
- 处理：歌名区加 ref，用 ResizeObserver 测量真实高度，页头高度 = 封面高 + 14 + 实测高度；测量前用单行值 114 兜底，切歌时重测。

## 104. 卡片控件内联手绘且深色岛 token 不全会导致浅色主题露馅。
- 原因：早先为了对齐 Folia 的动效，面板控件各自手写；深色岛又只钉了少数 token，宿主控件进岛后读到浅色值。
- 现象：播放卡片里行、分段、按钮、输入、滑杆都是内联样式手绘，宿主组件在卡片里不起作用，浅色主题下还可能「深底上贴一块白」。
- 处理：按规范 §3 选型换成 SetRow / KitSegmented / Button / IconButton / KitInput / .mp-range / .mp-set-label；卡面去掉与阴影叠加的 1px 描边；深色岛补齐宿主控件需要的 token。

## 105. 深色岛未固定 switch 轨道/滑块 token 会导致开关全白难辨。
- 原因：宿主 Switch 读 --dsw-alias-brand-primary（轨道）与 --dsw-alias-switch-thumb（滑块），深色岛只钉了文字/表面 token；浅色主题下这两个 token 解析成近白，滑块和轨道同色。
- 现象：卡片「显示译文」的开关整块白色，开与关分辨不出。
- 处理：在 .mp-card 作用域把这三个 token 钉成深色主题同一组静态来源（--dsw-static-neutral-bluish-50 轨道、-400 关态滑块、-1000 开态滑块），不要手写近似的十六进制，否则和组件测试页的官方开关始终差一点色。

## 106. clamp 正文高度只减固定底距会导致矮窗口分页被裁。
- 原因：卡片的 maxHeight 按「100dvh − 顶边距 − 真实锚点」算，但正文高度的 clamp 只减固定 MP_BOTTOM_GAP（24px），没减真实 bottom 锚点（约 90px），正文多算一截，把 dock 挤到裁剪线以下。
- 现象：窗口高度较小（或缩放窗口后）播放卡片展开，底部的 歌曲 / 歌词 / 音频 / 外观 分页被窗口下沿裁掉。
- 处理：clampCardBodyHeight 接收 viewport 与真实 cardBottom，正文 room 扣掉 padding、folded header、dock、dock gap 与正文自身 gap/line/under；maxHeight 用同一个 cardMaxH；封面高度按剩余空间封顶；窗口 resize 重新夹紧。

## 107. 卡片偏移只写 React state、不写 lyricOffsetMemory 会导致重开丢失。
- 原因：卡片把 onOffsetChange 直接接到了 setOffsetMs，只更新 React state；歌词页的 ± 按钮走的是 applyOffset，会写 rememberLyricOffset（Folia 的 lyricOffsetMemory）。重新加载歌词时 loader 用 readSavedLyricOffset 还原已保存值，于是没被记住的卡片调整被覆盖。
- 现象：在播放卡片「歌词」页把时间轴偏移从 0 调到 ±N ms，关闭卡片再打开（或重新进播放页），偏移又回到 0。
- 处理：新增 setLyricOffset(value) 统一做「state + 记忆 + 本地 calibrate」，applyOffset(delta) 改为调用它，卡片改接 setLyricOffset；数值统一夹在 ±60000 ms。

## 108. dock 子项默认 min-height:0 且 overflow 隐藏会导致空会话歌词条被压扁。
- 原因：歌词条挂在 conversation.input.dock，是宿主 composerStack 的一个 flex 子项。它默认 flex: 0 1 auto，又带 overflow: hidden，自动最小高度为 0；有对话时布局宽松，空会话的 hero 布局更紧，它就被压缩，内部图标和文字一起被裁。
- 现象：新建会话、还没有任何对话内容时，输入框上方的歌词条只有约 10px 高，图标和文字一起被裁掉上半截；发过消息后恢复正常。
- 处理：歌词条改为 flex: 0 0 auto + min-height（不再用可被压缩的固定 height），外层不裁剪，横向裁切只留给 viewport；加 position: relative; z-index: 2 防止被相邻层盖住。

## 109. MSE 无背压超 12MiB 配额会导致长音频停在 0:00。
- 原因：playOnlineMse 的 read()/pump() 没有背压，整首约 15.4 MiB 的音频被快速 append 进 SourceBuffer，超过 Chromium 约 12 MiB 的音频配额后抛 QuotaExceededError；fallbackToDirect() 只切换到直连，没有恢复已经被 playAfterLoudness() 置为 false 的 pendingAutoplay，直连流有效却仍处于暂停态。因为没走 onError、直连也没 error/ended，autoSkipUnplayable 不触发。
- 现象：网易云等在线源的长曲目（约 6 分钟以上的 320 kbps MP3）点播放后队列停在这首歌，进度始终 0:00；没有明确报错，也不自动跳下一首，重启 DSH 无效（issue #31）。
- 处理：响应总字节超过 10 MiB 时直接走直连媒体元素（mpMseStreamTooLarge）；MSE 任意失败回退时用纯函数 mpFallbackPlaybackState 保留播放意图和当前进度；补 SourceBuffer 的异步 error 监听。直连/Range 请求在 Host 侧只允许同音质重签名，避免海外节点重试时中途降档把不同编码拼进同一个资源；客户端用 direct=1 标记直连。

## 110. 直连代理流写入 currentTime 被 Electron 丢弃会导致拖动回开头。
- 原因：直连回退把 Host 代理的 HTTP 流直接交给 <audio>；Electron 媒体栈在 readyState 已满时会把 currentTime 写入丢掉，Chromium 对代理资源的 seekability 也不等价于 CDN 原生资源（见第 82 条），于是 native seek 回到 0。
- 现象：部分在线歌曲（大文件、FLAC/MSE 不支持、MSE 失败后的直连回退）能正常播放，但拖动进度条后会从 0:00 重新播放；本地文件正常。
- 处理：startOnlineDirect 改为 startOnlineBlob：整段 fetch 成 Blob，loadActiveSource(blob URL)，媒体元素对本地对象做随机访问；缓存命中、大文件、MSE 不支持/MSE 失败都走它，MSE 仍负责未缓存短音频的流式起播。

## 111. 滑杆组件定义在渲染函数内部会导致拖动一格就重挂。
- 原因：TuningRange 定义在 PlayerSheetInner 内部。React 把函数本身当作元素类型，每次父级渲染都是新的类型，于是整棵子树卸载重挂，<input type=range> 的 DOM 节点被替换——浏览器原生拖动状态挂在节点上，第一步写完 prefs 触发重渲染，拖动就断了（也就是早期日志里的「重渲染后只走一格」）。音量滑杆 VolumeControl 是模块级组件、类型稳定，DOM 复用，所以不受影响。滚轮另有一层：按 step 走一格，量级远小于音量的 5%。
- 现象：播放卡片「外观」页的样式参数滑杆按住拖动只走一格，松开再按才动一步；滚轮每格只挪 1 个 step（对比度这类 step=0.01、滑杆约 70px，一格不到 1px），看起来完全没反应。底栏音量滑杆两者都正常。
- 处理：TuningRange/TuningLabel/TuningGrid 移到 player-sheet.js 模块作用域；滚轮统一走 primitives.js 的 useWheelStep + mpSliderWheelValue（一格 = 量程 5%，按 step 吸附），音量控件也改用它，二者从此是同一套。

## 112. 追加行高覆盖但虚拟步长不变会导致重启后列表字体变小、行距变空。
- 原因：6f177e3 在 p3-styles.js 末尾追加了一段「对齐播放队列」的覆盖块（.mpv3-row 56px、标题 13px、歌手 11px、封面 40px）。CSS 同选择器后声明者胜，于是覆盖了 76px/18px/54px 的基准；而 P3List 的虚拟步长 rowHeight 仍是 76，行槽内联 height=76px、行本身 56px，每行下方多出 20px 空档。theme.test.mjs 只匹配基准规则，追加块没被任何断言看到，测试因此全绿。
- 现象：更新后重启 DSH，全部歌曲列表的标题、歌手、专辑、时长都小了一号，行距反而更空；播放队列还是原样。
- 处理：删掉覆盖块，只保留「单行 + 省略」；列表回到 76px / 18px / 54px，与虚拟步长一致。

## 113. 字幕底距 shim 写死 0 会导致底部译文被胶囊压住。
- 原因：src/folia/hooks/usePlayerBottomBarBottomPx.ts 是插件版 shim，为了「Machi camera bar 贴页面底边」把 usePlayerSubtitleBottomPx() 写死返回 0。Folia 原版返回「底栏底距 + 80 净空」（桌面 112），字幕层就落在页边；.mp-shell-stage 的 padding-bottom: 96 只影响在流子元素，绝对定位的字幕层照样贴底。
- 现象：所有 Folia 歌词样式的底部译文都停在窗口最底边，播放胶囊（町景里就是那条胶囊）压在它上面；看起来像字幕忘了给底栏让位。
- 处理：shim 改为随胶囊让位：控制条在场 96px（本页胶囊底距 16 + Folia 的 80 净空），隐藏时 32px；町景的相机条同样受益。

## 114. 弹窗只认 provider prop 而右键只传 track 会导致永远说没有在线平台。
- 原因：OnlineAddToPlaylistDialog 只从 layer.props.provider 取平台，右键菜单 pushLayer('onlineAddTo', { track }) 只传了歌曲，星标传的是 { provider, song }；同一个弹窗两条调用方各写一套参数，缺一个就落到错误分支。Folia 的 picker 反过来，来源从歌曲自身读（getPlaybackSourceRef(song)，useAddToPlaylistStore / AddToPlaylistHost）。
- 现象：在线歌曲上右键 →「添加到歌单」，弹窗直接写「当前曲目没有在线平台」；播放页右下角星标打开同一个弹窗却能列出歌单。
- 处理：新增 onlineAddTarget(layerProps)（song || track，provider || song.onlineProvider），弹窗只用它；右键菜单补成 { provider, song }。

## 115. 弹窗正文无独立滚动容器会导致歌单多时被裁。
- 原因：本地与在线两个「加入歌单」弹窗都把列表直接塞进模态正文；正文只有 max-height，没有自己的滚动容器，超出部分被裁。Folia 的 PlaylistSelectionDialog 把行放进自己的滚动列表（st-scroll min-h-0 overflow-y-auto）。
- 现象：账号里歌单较多时，「加入歌单」弹窗只显示前几个，下面的看不到也滚不动。
- 处理：新增 .mp-pick-list（max-height:min(56vh,420px)、overflow-y:auto），本地/在线两个列表都套上；「新建歌单」输入行留在滚动区外。

## 116. 拿 specialid 请求概念版 playlist_track_all 会导致 20010。
- 原因：推荐行来自 m.kugou.com/plist，唯一的 id 是网页 specialid；歌单歌曲走概念版 playlist_track_all（/pubsongs/v2/get_other_list_file_nofilt），它要 global_collection_id，specialid 一律回 20010。实测：playlist_track_all 传 specialid → 502；playlist_detail ids=specialid → data 为空（解析不出来）；mobilecdn special/song?specialid= → 正常…
- 现象：酷狗「推荐」里的歌单点进去 0 首歌，只有「加载失败 · 酷狗概念版请求失败（code=20010）」。
- 处理：getRecommendedCollections 照 Folia 换成 6 张卡（读空的卡不出）；playlistSongsPage / playlistSongs 认 kugou-card- 前缀读卡本身，数字 specialid 走接受 specialid 的公开页读取器；kugouKnownNotAccountPlaylist 借 30 秒的账号歌单缓存跳过注定失败的概念版尝试。

## 117. 把 tid 当 dirId 会导致 QQ 加入歌单失败或假成功。
- 原因：歌单卡片的 id 是 tid（/user/playlist 的 tid 优先），而 musicu AddSonglist 要 dirId（本账号文件夹号 1–199）；旧代码 addSongToPlaylist(raw, playlistId, 0, cookie) 把 tid 填进了 dirId。Folia 的写入走包路由 /user/playlist/tracks（按 tid 自己解析 dirId，并校验 dirId<200、dirType=0）。
- 现象：QQ 账号右键「添加到歌单」→ 选自己的歌单 → 提示加入失败，或看起来成功但歌单里没有。
- 处理：新增 qqPlaylistWriteTarget（Folia canAddToPlaylist：本账号普通歌单 + tid + 非「我喜欢」）与 tid 版 addSongToPlaylist（/user/playlist/tracks，op: 'add'；changed:false 时按 verification.status === 'present' 判成功）；「我喜欢」走红心；删掉 qq-legacy 里 dirId 版的 add/delete。

## 118. 选择框不过滤平台可写目标会导致选出写不进去的歌单。
- 原因：/online/my-playlists 把账号里的全部歌单交给选择框；各平台规则不同（Folia 用 mutations.canAddToPlaylist 过滤）：QQ 只认本人普通歌单，酷狗只认自建歌单，酷狗「我喜欢」是红心，收藏歌单不属于自己。
- 现象：选择框里有「我喜欢」和收藏来的歌单，点下去却失败（QQ、酷狗尤其明显）。
- 处理：Host 给歌单行加 addable（QQ / kugouLite / 波点各自判定；其余不设规则＝与 Folia 一致），OnlineAddToPlaylistDialog 用 onlineAddPlaylists() 过滤；没有可写目标时显示「没有可用的歌单」。

## 119. 概念版移除用标准版 worker 会导致凭证错配、移除失败。
- 原因：removeOnlineSongFromPlaylist 对 kugouLite 也调标准版 KG.deleteSongFromPlaylist；概念版 appid/clientver 与标准版不同，listid/fileid 属于概念版账号——和第 88 条云盘是同一类凭证错配。
- 现象：概念版账号在歌单页移除歌曲失败。
- 处理：kugou-lite.js 新增 removeSongFromPlaylist（playlist_tracks_del，概念版签名 + listid/fileids），removeOnlineSongFromPlaylist 按 provider 分派。

## 120. 能力表漏声明 playlistTrackMutations 会导致移除入口与路由被挡住。
- 原因：KUGOU_LITE_CAPABILITIES 只声明了 playlistAdd，没声明 playlistTrackMutations（也没开 mutations）。adapter.js 的 allowedBy 用 METHOD_CAPABILITY.removeFromPlaylist = 'playlistTrackMutations' 挡请求，客户端的 canRemove 也读同一个标记——实现写了，入口和路由一起被自己挡住。Folia 的 kugou provider 同时声明 mutations 与 playlistTrackMutations。
- 现象：酷狗概念版歌单页从来不显示「从当前歌单移除」，/online/playlist-remove 也一律拒绝；加歌单却正常。
- 处理：概念版补声明两个能力；/online/my-playlists 注入的排行卡片补 addable: false。新增 test/host/online-capabilities.test.mjs：对每个「能力 → 方法」用哨兵上游逐平台调用，只有「未知平台」和「does not support」算失败。

## 121. 分页 nextOffset 用归一化后行数会导致酷狗歌单整页重复。
- 原因：getMyPlaylistSongsPage 用 nextOffset = at + songs.length，而 songs 是 normalize 之后剩下的行。第 1 页 100 行里有一行没有 hash 被丢掉 → nextOffset 99；下一次 page = floor(99/100)+1 = 1，又把第 1 页取了一遍。客户端合并时读的是 Host 行上根本不存在的 path，于是整页被当成新歌追加。实测：raw page 100 行 → KGL 99 行 → next 99 → offset 99 请求返回的正是第 1 页（99 行全部重复）。
- 现象：酷狗「我喜欢」歌单往下滚，之前出现过的歌按原顺序又出现一遍（实测 258 首的列表，翻页后同一批歌反复出现）。
- 处理：游标按这一页实际吃掉的原始行前进（pageStart + rows.length）；页号由 offset 除以「上游实际服务的页大小」得出（首屏学到 stride，上游把 100 压成 30 就按 30 走）；客户端 onlineSongKey（provider:id）做页内去重与合并，并在游标不前进时结束列表。同一条规则一并修到网易云、酷狗标准版、波点、汽水的分页读取器。

## 122. 歌手页硬切前十且无全部歌曲分页会导致几百首只能听十首。
- 原因：p3 歌手页把已加载列表 items.slice(0, 10) 硬切；宿主只有网易云会补拉 200 首，QQ/酷狗首请求只拿一页（QQ 80、酷狗 60），客户端也没有「全部歌曲」这一层。Folia 是两层：页面只拿热门 10 首（ARTIST_TOP_SONG_LIMIT），另有「全部歌曲」集合按 offset 翻页（open-all-songs）。
- 现象：点进歌手，页头写着「417 首歌」，但「热门歌曲」只有 10 首，往下滚没有更多，其余的歌看不到。
- 处理：artistSongs 改成 page 形状（songs/total/hasMore/nextOffset）——QQ 用 total_song、网易云用 more/total、酷狗用响应顶层 total（实测 1143/3196 均可翻页），名称搜索与 Navidrome 一次性读取 hasMore=false；p3 歌手页保留热门 10 首 +「全部歌曲 · N」，后者用 P3List 每页 100 首、游标取 Host 的 nextOffset；搜索页改为按 Host 的 hasMore 显示「加载更多」。

## 123. 汽水 ticket guard 过期未续期会导致账号类读取全部 auth-required。
- 原因：汽水的账号请求走 ticket guard（bd-ticket-guard-* 头），票据约 6 小时过期，过期后平台回 28001008。包里的续期只挂在 login_status（auth.status() → 刷新 access_code → 新 ticket → /me/info/ 验证 → sessions.set），我们的 request() 从不调用它，平台原句就直接冒到页面。Folia 的桌面桥是原样透传，同样没有续期这一步。
- 现象：汽水音乐的歌单页「加载失败 · Qishui rejected the request」；搜索还正常，只有账号类读取（歌单、喜欢的歌、最近播放）失败。
- 处理：src/host/providers/sources/qishui/index.js 的 request() 在账号读取失败且 code=auth-required、upstreamCode 非空时，先调一次 login_status 续期（续期会把新会话写回 sessions 存储），成功则重放原请求一次；续不上（无会话/被拒）给「汽水登录已过期，请在「设置 → 在线」重新扫码登录」，不再把平台原句直接给用户。login_* 操作自身不触发续期，避免循环。

## 124. 播放模式不统一成一颗按钮且不留 baseQueue 会导致原顺序无法还原。
- 要点：规则（产品确认，不是 Folia）：顺序播放 → 单曲循环 → 随机播放 → 顺序播放，始终一颗按钮（底栏、播放页胶囊、播放页右侧同一套）。音频设置里不再有第二套「播放模式」控件。
- 状态：state.queue 是"正在播放的顺序"，state.baseQueue 是原顺序，state.playMode 是模式（sequence/one/random）。随机时 queue = [当前歌, ...其余随机]；切出随机（顺序或单曲）按 baseQueue 还原，并把 index 指回正在播的那首；再次进入随机重新生成一张表（不复用上一张）。随机表放完一轮按 loop='all' 回到表头循环，不自动重洗；重启保留当前随机表与 baseQueue（playback.json 的 playMode/queue/baseQueue…
- 队列编辑：非随机模式下 move/reorder 同步写 baseQueue；随机模式下拖拽只改随机表、不动原顺序；增删歌两边同时同步。

## 125. 版本检查缓存 1 小时且失败静默会导致新版本提示延迟或不出现。
- 来源：npm registry /dsh-music-panel/latest → npmmirror 镜像 → GitHub Releases 的 tag_name（按顺序，第一个成功即停）；Host 用已安装 package.json 的 version 做 current。checker 的 PLUGIN_ROOT 是 src/host/services/update/checker.js 往上 五级，少一级会得到空 current（测试用默认 readVersion 钉住）。

## 127. 自研酷狗与上游各写一套会导致签名/VIP/取流反复不同步。

## 128. 四个平台各自自研而不共用桥接会导致重复实现与行为分叉。

## 130. 只拷音源歌词接口、漏宿主 lyricsSource 会导致平台歌词整段空白。
- 原因：音源 lyrics@1.getLyrics 只给 { main: { format, text }, wordByWord: { format, text } }（原始文本 + 格式）。Folia 的宿主在 src/mods/folium/lyricsSource.ts 的 resolveFoliumSourceLyricsResult 里依次做：校验 track → 逐字轨借用逐行轨的翻译/罗马音 → parseLyricsByFormat（worker）解析 → 行文本 chorus 规则。移植时只搬了音源定义…
- 现象：酷狗（以及 netease / qq / bodian / qishui）的歌播放时有的有词、有的空白；有词的都是 AMLL 跨源补的（lyric-states.json 里 matched.source: amll、lyric: null）。

## 131. 镜像不按上游根 1:1 且无校验脚本会导致路径自创与内容漂移。
- 为什么：镜像原来分在两套前缀（src/folia/ 对应上游 src/，src/folia-mods/ 对应上游 sources/、packages/），每次移植都要想路径怎么摆；且没有脚本能发现镜像里混进上游不存在的文件、或内容悄悄漂移。
- 现在：镜像统一在 folia/，与上游仓库根 1:1：folia/src/、folia/sources/<id>/、folia/packages/<包>/。镜像是最小子集；上游多出来的文件不搬（--list-missing 可查）。替换上游模块的替身在 src/folia-adapters/<上游相对路径>，文件头写「替身上游：…」。
- 校验：node scripts/check-folia-mirror.mjs（已并入 npm run check 与 npm test）。默认要求逐字节相同；确有插件适配的 52 个文件登记在 folia/mirror.manifest.json（含登记时的上游 SHA256，上游一变就报错）。不要为了让校验通过去改清单里没登记的文件——先判断是「上游漂移该刷新」还是「需要适配该登记」。

## 132. 归一化丢掉原始付费字段会导致 VIP 角标与跳过判断失效。
- 原因：这个角标是插件自己的特性，规则原本写在旧 provider 映射里：netease fee===1、qq payplay===1、bodian payInfo.feeType.vip==='1'、qishui commerce_info.icon_info.type 为 vip/svip。移植后原始响应由音源归一化吞掉，DTO 只剩 availability 文案。
- 现象：对齐 Folia 在线源之后，VIP/付费曲目不再显示 VIP 角标（qualityHint），“跳过 VIP 曲目”的判断也随之失效。

## 133. 试听靠播放后时长猜、失败不分类会导致提示错位与规则不一致。
- 为什么：音源层早已原样移植，但宿主层还留着自写规则：试听提示靠“播起来后时长不足一半”判断、autoSkipUnplayable 默认开、失败只有一句笼统提示。
- 试听：上游的 getAudioSource 会把试听片段标成 preview: true，宿主在播放前据此提示。插件里浏览器只拿 <audio src>，读不到这个标记，所以新增 /online/stream-info（只解析、不转发字节，复用 Host 的 streamUrlCache）让客户端播放前先问一次；客户端据此在出声前弹 online.previewOnly。顺序：先问 /online/cache-info，命中缓存就直接播（缓存是整曲播完后写的，不能被平台问询挡住），未命中才过这道门。

## 134. 试听时长用 max(媒体,目录) 且时钟不加 clipStart 会导致时长与歌词错位。
- 为什么：上游把「平台只给试听」当成媒体文件本身处理：舞台时长读媒体元素，歌词时钟是 currentTime + clipStartMs。插件原来把时长算成 max(媒体, 目录)，试听时永远显示整曲长度，进度条按整曲走；歌词时钟也没加片段起点。
- 时长：src/client/services/player/duration.js 的 effectivePlayerDuration(mediaDuration, trackDuration, preview) 在 preview === true 时返回媒体时长（没有才退回目录）。播放器在 onTime 里（session.preview 时）从 audio.duration 同步 state.duration；MSE 只报已追加前缀时用 audio.buffered 末端兜底。所有显示时长的地方（播放页、胶囊、进度条、传输胶囊、状态栏、p3 面板）都把这个 preview 传进去。
- 歌词：Host /online/stream-info 返回 clipStartMs（bridge/酷狗门面从上游 getAudioSource 的 clipStartMs 透传；音源没给就是 0）。客户端 session.clipStartMs → getTime()/getPlaybackTime() → 播放页 lyricClock(currentTime + clipStart)、两套 Folia 舞台的 readTime()、作曲栏与状态栏；舞台歌词行点击 seek 用 - clipStart + offset 映射回元素时间。

## 135. 取流只传 id、不带 songmid 侧车会导致 QQ 报「QQ song has no songmid」。
- 原因：QQ 的播放键不是 id：数字 songid 才是 publicId，songmid 在 lyricIds.qq / data.songMid，mediaMid 在 data.mediaMid；HTTP 路由只带 provider + id。

## 136. bundle 内联依赖路径随 pnpm/npm 布局变化会导致 CI 判 STALE。
