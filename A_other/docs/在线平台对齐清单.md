# 在线平台对齐清单（对照 Folia）

这份清单解决的是同一类事故：**同一个东西在不同接口里有不同的 id**、**能力声明和实现对不上**、**读写用了不同客户端**。酷狗的 `specialid` / `global_collection_id`、QQ 的 `tid` / `dirId` 都是这一类。以后动在线平台相关代码，先过一遍本文。

## 1. 第一性原理：id 归谁

一张卡片在一个接口里生产出来，就必须能被同一套「读取器」读懂。生产与读取各自要的 id 不是同一个时，**转换只允许发生在 Host 的一处 helper 里**，不许散在路由或客户端。

| 面 | 谁生产 id | 读取/写入要什么 | 转换在哪 |
|---|---|---|---|
| 在线歌曲 | 搜索/歌单/专辑/排行 | 取流、歌词、红心、加入歌单要「歌曲 id」 | 网易云：数字 id；QQ：songmid；酷狗：hash。`shape()` 统一出 `id`，各平台模块自己认 |
| 在线专辑 | 搜索/歌手页/专辑页 | 专辑曲目接口要「专辑 id」 | 网易云：数字 id；QQ：albummid；酷狗：数字 album id，缺失时用专辑名回退搜索（`albumSongs`） |
| 歌单卡片 | 推荐/搜索/分类/我的歌单 | 歌单歌曲接口要「歌单 id」 | 网易云：数字歌单 id（无需转换）；QQ：tid（写入时包解析 dirId）；酷狗：见下 |
| 酷狗推荐卡 | 概念版卡片 | 读卡片自己 | `kugouRecommendationCardId` + `getRecommendationCardSongs`（`kugou-card-<card_id>`，本地虚拟歌单） |
| 酷狗公开歌单 | 搜索/分类/网页 | 网页 `specialid` | `playlistSongsPage` 的数字分支 → 公开页读取器（概念版 cloudlist 要 `global_collection_id`，传 specialid 必回 20010） |
| 酷狗我的歌单 | `user_playlist` | cloudlist 读歌要 `listid`/`global_collection_id`；写入要 `listid` | `KGL.getMyPlaylists`（id = gcid 或 listid）+ `kugouPlaylistSongs` / `KGL.addSongToPlaylist` |
| QQ 我的歌单 | `/user/playlist` | 卡片 id = tid；包写入路由 `/user/playlist/tracks` 按 tid 解析 dirId | `qqPlaylistWriteTarget`（本账号普通歌单才可写） |
| 排行卡片 | Host 合成 `listening-rank-<range>-<account>` | `/online/playlist-songs` 特判 | 路由内；这类行 `addable: false`，不进「加入歌单」 |

## 4. 与 Folia 的设计差异（有意的取舍）

- **一层扁平 facade + 平台模块**，不是 Folia 的 namespace 对象。等价契约仍在 `contract.js` 的 `PROVIDER_API_GROUPS` / `METHOD_CAPABILITY`，能力门在 `adapter.js`。
- **请求全部在 Host（Node）**，Folia 一半在 renderer、主进程负责平台桥接。所以「读写必须同一个客户端」这件事在我方完全由 Host 自己保证（概念版 vs 标准版两个 worker）。
- **能力集合是 Folia 的子集**：没实现的能力不声明，界面上就不会出现入口。
- **Host 直接写中文文案**（无 i18n）；客户端只做展示。

## 5. 已知差距（不是 bug，但没有对齐）

- 酷狗歌单订阅/取消（Folia 的 `playlist_add` / `playlist_del`）未接：`playlistSubscription` 未声明，订阅按钮不出现。
- 酷狗「收藏的专辑」列表（Folia `userAlbums`）未接。
- 网易云的订阅歌单仍会出现在「加入歌单」里（Folia 也没给 netease 写 `canAddToPlaylist`）；上游拒绝时只有一句报错。
- 汽水的歌单行没有 owned 标记（其响应只有 `ownerId`），所以没有 `addable` 规则；Folia 的 `qishuiMutations` 规则需要该标记。
- 波点/汽水不在 `UI_SOURCES`，靠 `/online/providers` 动态追加；它们的推荐/订阅能力未声明。
- QQ / 酷狗的写入只用 stub 上游 + 包自带的校验源码验证过，**没有用真实账号复验**（写歌单、移除）。
- Folia 的 FM 模式、不喜欢换一首、推荐偏好、外部播放等高级能力未接（未声明）。

## 6. 动在线平台代码时的必做清单

1. **先写 id 归属**：这次改动的「生产方」与「消费方」各自要什么 id？不同就加一处转换 helper，并在 helper 注释里写清两边是什么。
2. **读写同一客户端**：概念版/标准版/第三方包不许混用 worker（第 88、119 条踩坑）。
3. **能力与实现同一次提交**：实现了写入就要声明对应能力，否则入口与路由都被能力门挡住（第 120 条）。
4. **选择框只列可写目标**：Host 给行标 `addable`，客户端不按平台分支（第 118 条）。
5. **分页游标**：`nextOffset` 必须按上游这一页**实际返回的行数**前进，不是按规范化后剩下的行数；页式接口的页号必须由 offset 除以**上游实际服务的页大小**得出。少走一格会让下一页落回同一页，整页被重复追加（酷狗歌单整页重复就是这么来的）。游标不前进时 `hasMore` 必须是 false。
6. **平台规则留在平台模块**：facade 只分派，不写「QQ 只认 dirId」这类平台细节。
7. **补测试**：能力一致性 + 本平台的 id 空间用例（见下）。
8. **有真实账号时先跑一次读 + 一次写**，再声称「对齐完成」。
