# Folia 上游移植规范

适用于把 Folia 的功能搬进 `dsh-music-panel`。核心只有一句话：

> **先复制 Folia 源码，再改插件接线；不要看懂后重写。**

Folia 是独立客户端，我们是 DSH 插件。两者外部接口不同，但业务行为必须一致。

## 1. 三层结构

```text
Folia 原始实现（src/folia/ 或功能目录）
        ↓ 只替换 import 和外部依赖
插件适配层（store / player / HTTP / 窗口 / 主题）
        ↓
插件界面挂载（DSH 面板）
```

| 层 | 做法 | 允许改什么 |
|---|---|---|
| Folia 源码 | 原样复制 | 基本不改；只改 import 路径 |
| 适配层 | 新建薄封装 | 把 Folia 的 store、播放器、IPC、在线接口换成插件接口 |
| 界面层 | 挂到插件页面 | 只做主题 token、宿主控件外观、挂载生命周期 |

## 2. 必须保留

```text
算法和布局计算
动画曲线、持续时间、缓动
交互顺序和状态切换
暂停 / 恢复 / seek / 切歌行为
队列、歌词时钟、音频分析
异常分支、降级路径、边界条件
默认值、文案语义、用户可见行为
```

这些不是“实现细节”，而是行为本身。不能因为插件代码更顺手就换写法。

## 3. 只允许适配的地方

```text
Electron / 主进程 / IPC     → 插件 Host HTTP 接口
Folia 的 player store        → 插件播放器接口
Folia 的 settings store      → 插件 prefs
在线音乐 provider 调用       → 插件现有 provider / omni
窗口、路由、生命周期         → DSH 面板挂载
资源路径、公共目录           → 插件资源路径
Folia Tailwind / 自有 token  → DSH token 和宿主控件外观
```

适配层只做“翻译”，不改变调用语义。

## 4. 前端页面改动必须先确认

默认只移植内部逻辑；任何页面结构、页签、设置行或控件布局改动都要先向用户确认。

```text
内部逻辑：状态机、播放、队列、歌词、搜索、缓存、错误处理
前端页面：先问用户，确认后再改
未经确认不新增页签、设置行或控件布局
```

如果 Folia 的功能依赖一个新页面/新页签，而本插件没有对应页面，先把逻辑移植成可调用的内部能力；页面入口单独向用户确认。

## 5. 外观可以 DSH 化，行为不能

- Folia 的结构、尺寸、动效、交互照搬；
- 颜色、圆角、阴影、字体换成 DSH token；
- 宿主控件只替换外观，不替换行为；
- 如果 DSH 控件行为和 Folia 不一致，**保留 Folia 控件，只换皮肤**，不要换成行为不同的控件。

## 6. 移植步骤

```text
1. 找到 Folia 对应源文件、依赖和上游提交
2. 原样复制到插件目录
3. 列出它依赖的所有外部接口
4. 只把这些接口换到适配层
5. 用插件构建链打包
6. 对照 Folia 逐项验收行为
7. 提交时写清来源文件和适配差异
```

## 7. 四种移植标记

| 标记 | 含义 | 例子 |
|---|---|---|
| `直接复制` | 除 import 外不改 | 纯计算、常量、工具函数 |
| `适配复制` | 复制后替换外部接口 | 播放器、在线源、存储 |
| `包装挂载` | 外面加插件生命周期壳 | 面板入口、窗口级组件 |
| `无法复制` | 依赖 Electron 独有能力 | 必须记录原因和替代行为 |

前三种是常态。`无法复制` 不能偷偷重写，必须先记录差异。

## 8. 文件头写法

每个移植文件在文件头写清楚来源：

```js
/**
 * 移植自 Folia:
 * src/components/panelTab/shell/PanelShell.tsx
 *
 * 适配：useBottomDockStore → 插件底部栏接口
 */
```

这样以后 Folia 更新时能按路径找回上游。

## 9. 验收清单

```text
[ ] Folia 源码文件已原样复制
[ ] 所有外部依赖都有明确适配点
[ ] 没有为了“插件方便”改写算法
[ ] 动画、时序、默认值一致
[ ] 暂停、seek、切歌、异常输入行为一致
[ ] 视觉只替换 token / 宿主外观
[ ] Folia 更新时能按文件头回到上游
[ ] 相关测试已补
```

## 10. 一句话检查

如果 Folia 源码更新后，我们能按文件头找到原文件并对照 diff，说明移植是合格的；如果只剩“看起来差不多”的插件代码，就是重写，不是移植。

## 11. 目录结构

`src/folia/` 是 Folia `src/` 的镜像，不是插件杂物间。

```text
src/folia/          已移植的 Folia 文件，相对路径必须与上游一致
src/folia-adapters/ 插件适配层：shims、vendor、插件特有实现
src/folia-build/    构建入口与 bundle
```

规则：

```text
1. 已移植文件按上游相对路径放置，不改目录名
2. 插件独有文件不放进 src/folia
3. 构建入口、bundle、Tailwind 产物不放进 src/folia
4. 以后按路径 diff 时，src/folia 与上游 src 应能直接对上
```
