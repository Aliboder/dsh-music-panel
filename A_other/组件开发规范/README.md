# DSH 组件开发规范（通用版）

> 对齐 DeepSeek Harness 官方组件与设计 token；适用于任何 DSH Client 插件。
> 核对基线：DSH 0.2.2-rc.5（宿主原语与 CSS 均来自该版本的实际产物）。
> 本文件夹可整体复制到任意插件仓库，不依赖任何具体插件的代码或路径。

## 给 AI 的阅读顺序

```text
1. 本文 README（使用方式与约定）
2. 01-核心原则.md（必须遵守的六条）
3. 02-宿主组件加载.md（host-ui.js）
4. 03-适配层规范.md（适配层契约）
5. 04-组件/ 里本次要用的组件页（每页自包含）
6. 05-组件测试页.md（立用例）
7. 08-验收清单.md（提交前逐条过）
8. 09-升级复核.md（DSH 升级后才需要）
```

写界面前先读 01～03；写某个控件时只读它对应的 04 页；**不要**跳过测试页直接写业务控件。

## 一句话规则

**测试页长什么样，业务里就只能长什么样；测试页没有的控件，不许上界面。**

## 复制给 AI 的开场指令

## 接入一个新插件

1. **复制加载器**：`模板/host-ui.js` → `src/client/app/host-ui.js`，按 `manifest` 顺序加载；
2. **复制适配层**：从 `模板/primitives.example.js` 取本次要用的函数，放进 `src/client/components/ui/primitives.js`；
3. **改前缀**：模板统一用 `ui-` 作为 CSS 类前缀、`Kit*` 作为适配层名；把 `ui-` 换成你的插件前缀（全局替换即可，不要只改一半）；
4. **立测试页**：`模板/component-gallery.example.js` + `05-组件测试页.md`，每个控件至少一个默认态 + 一个非默认态；
5. **过验收**：`08-验收清单.md`；DSH 升级后按 `09-升级复核.md` 复核。

## 约定

- **前缀**：模板用 `ui-`；你的插件可以换成 `myplugin-`，但同一个仓里必须统一。
- **适配层命名**：宿主组件用原名（`Button` / `Switch` / `Modal` / `Menu`），需要包装的用 `Kit` 前缀（`KitInput` / `KitSegmented` / `KitModal`），本地组合用名词（`IconButton` / `SetRow`）。
- **onChange 语义**：`Switch` / `Checkbox` 收 boolean；`Input` 收 `(value, event)`；`Segmented*` / `Menu` 收 value/id 字符串。
- **CSS**：只用 `--dsw-alias-*` / `--dsw-static-*` / `--dsw-radius-*` / `--dsw-elevation-*`，禁止写死颜色。
- **发丝线**：`.5px`，不要 `1px`。
- **文档**：本文件夹内的说明文档用中文名；代码模板用功能性文件名。

## 自检

```bash
node 脚本/check-kit.mjs
```

它会检查：相对链接是否存在、契约 JSON 是否可解析、每个组件是否都有文档、CSS 是否写了硬编码颜色、几何常量是否齐全、是否混入了具体插件的专用词。
