# 09 升级复核

DSH 升级后，宿主的 props 与 CSS 可能变化。按本页重新核对，再改代码。

## 1. 找到宿主产物

桌面端安装包（示例路径）：

```text
<DSH 安装目录>/resources/app.asar
```

asar 结构：

```text
offset 0   uint32  pickle 大小
offset 4   uint32  头部长度（旧字段）
offset 8   uint32  JSON 字节长度
offset 12  uint32  JSON 字节长度（以这个为准）
offset 16  JSON 头
数据起点   16 + JSON 字节长度
```

前端产物：

```text
dsh/node_modules/@deepseek-ai/dsh-web-frontend/dist/assets/index-*.js
dsh/node_modules/@deepseek-ai/dsh-web-frontend/dist/assets/index-*.css
```

## 2. 读原语导出表

在 JS 里搜：

```text
const DK=Object.freeze
```

`DK` 是 `@deepseek-ai/dsh-client-ui-primitives` 的命名空间，里面有 `Button` / `Switch` / `Input` / `Checkbox` / `SegmentedControl` / `SegmentedTabs` / `Pill` / `Tag` / `StateDot` / `Tooltip` / `Modal` / `Menu` / `Toast` 等。

按导出名找到对应的压缩函数，读它的参数解构即可得到 props 列表。

## 3. 读 CSS

在 CSS 里搜这些类名前缀：

```text
_switch_   _thumb_
_control_  _indicator_  _tab_
_tabs_
_button_   _sm_  _md_
_pill_     _tag_
_wrap_     _input_
_checkbox_
```

逐项对照 `04-组件/` 与 `参考/` 里的值：高度、内衬、圆角、字号、指示块、开关滑块、token 名。

## 4. 核对流程

```text
1. 读导出表 → 更新 参考/ 的签名表
2. 读 CSS   → 更新 参考/ 的 CSS 摘录
3. 对比 04 页与 fallback CSS → 有差异先改测试页与 fallback
4. 跑测试页：native / fallback、浅色 / 深色、窄宽度
5. 更新 契约/components.json 与 契约/geometry.json
6. 更新 README 的版本号与日期
7. 提交时写清「对齐 DSH x.y.z」
```

## 5. 兼容策略

- **新增**导出：可以立即用；先在测试页加用例。
- **修改**props：适配层做兼容（新旧都接受），业务代码不动。
- **删除**导出：适配层自然回退到 fallback；测试页补提示。
- 宿主包整体不可用：全部 fallback，关于页显示 fallback 状态。

## 6. 别做的事

- 不要因为升级就改业务调用方；适配层是唯一改动点。
- 不要把宿主 CSS 的 hashed 类名抄进 fallback；抄值，不抄类名。
- 不要在 fallback 里写死宿主版本号。
