# 03 适配层规范

适配层是业务代码与宿主组件之间的唯一桥梁。业务只认适配层，适配层负责宿主/fallback 两条路径。

## 1. 适配层契约

| 适配层 | 宿主导出 | 业务侧 onChange | 说明 |
|---|---|---|---|
| `Button` | `Button` | `onClick(event)` | 默认 variant 由适配层决定（建议显式传） |
| `IconButton` | 无（Tooltip + `<button>`） | `onClick(event)` | 必须有 `title`（同时作为 aria-label） |
| `Switch` | `Switch` | `onChange(boolean)` | 宿主 `onChange` 收到的是取反后的值 |
| `KitInput` | `Input` | `onChange(value, event)` | 宿主 `onChange` 是原生事件，适配层取 `event.target.value` |
| `KitCheckbox` | `Checkbox` | `onChange(boolean)` | 宿主 `onChange` 收 `event.target.checked` |
| `KitSegmented` | `SegmentedControl` | `onChange(value)` | value 一律字符串；每实例唯一 id |
| `KitSegmentedTabs` | `SegmentedTabs` | `onChange(value)` | items 带 `id` 与 `panelId` |
| `KitPill` | `Pill` | `onClick(event)` | 无 `onClick` 时宿主渲染 `<span>` |
| `KitTag` | `Tag` | 无 | `tone` 八种：outline/solid/neutral/quiet/success/info/warning/danger |
| `KitStateDot` | `StateDot` | 无 | `state`：done/warning/error/idle/ongoing |
| `KitModal` | `Modal` | `onClose()` | 调用方按需挂载，`open` 恒为 true |
| `KitSelect` | `Menu` | `onChange(id)` | 触发器 + 宿主菜单 |
| `SetRow` | 无 | 无 | 设置行骨架（label/desc/control） |

## 2. 标准骨架

```js
function AdapterName(props) {
  // 1. 先归一化业务侧语义（字符串、布尔、默认值）
  var value = String(props.value === undefined ? '' : props.value)

  // 2. 宿主可用就渲染宿主
  var Host = hostComponent('HostName')
  if (Host !== null) {
    return h(Host, {
      // 只传宿主认识的 props；语义转换在这一层完成
      value: value,
      onChange: function (next) {
        if (typeof props.onChange === 'function') props.onChange(next)
      },
      label: props.label || '',
      className: props.className,
    }, props.children)
  }

  // 3. fallback 的 DOM 语义与宿主一致
  return h('div', { className: cx('ui-adapter', props.className) }, props.children)
}
```

三条硬约束：

1. **业务 props 只在这一层翻译**：不要把 `checked` / `value` 这类宿主命名漏到业务里；
2. **fallback 与宿主同 DOM 语义**：`role`、`aria-*`、`tabIndex`、键盘事件都要有；
3. **无副作用地读 hostComponent**：每次渲染都判断，不缓存结果。

## 3. value 与 id

宿主的 `SegmentedControl` 用 `===` 比较 value，并派生 `${id}-${value}` 与 `${id}-${value}-panel`。因此：

```js
// 统一字符串
var value = String(props.value === undefined ? '' : props.value)
// 每个实例唯一 id
var idRef = useRef(null)
if (idRef.current === null) {
  KIT_SEQUENCE += 1
  idRef.current = 'ui-seg-' + String(KIT_SEQUENCE)
}
var id = props.id || idRef.current
```

分页的 `panelId` 必须指向真实面板：

```js
items: [{ value: 'a', label: 'A', id: 'ui-tab-a', panelId: 'ui-panel-a' }]
// 面板：<div id="ui-panel-a" role="tabpanel" aria-labelledby="ui-tab-a">
```

## 4. 命名与前缀

| 类型 | 模板写法 | 你的插件 |
|---|---|---|
| CSS 类 | `ui-btn`、`ui-switch`、`ui-segment` | 换成你的前缀，全局替换 |
| 适配层 | `Button`、`KitInput`、`IconButton`、`SetRow` | 保持，避免多套命名 |
| 内部变量 | `KIT_SEQUENCE`、`hostComponent` | 保持 |
| 事件 | `onChange` / `onClick` / `onClose` | 保持 |

前缀替换检查：

```text
[ ] CSS 类全部换完（grep 旧前缀 = 0）
[ ] 模板里的示例文件名/注释没有旧前缀
[ ] 测试页的 prefix 说明同步
```

## 5. fallback 的编写顺序

1. 先写结构（与宿主相同的标签层级、role、aria）；
2. 再写几何（高度、padding、圆角、字号，对照 06 与参考页）；
3. 再写颜色（只用 token）；
4. 最后写交互（hover 只在 `@media (hover: hover)`、disabled、focus-visible、过渡）。

顺序反过来做，最容易出现「颜色像、布局不像」的假等价。
