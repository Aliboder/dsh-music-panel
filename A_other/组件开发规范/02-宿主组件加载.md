# 02 宿主组件加载

## 1. 唯一的 require 入口

```js
// src/client/app/host-ui.js
var hostUi = null
try {
  hostUi = require('@deepseek-ai/dsh-client-ui-primitives')
} catch (error) {
  hostUi = null
}

function hostComponent(name) {
  if (!hostUi) return null
  var value = hostUi[name]
  if (typeof value === 'function') return value
  if (value && typeof value === 'object' && value.$$typeof) return value
  return null
}

/** 面板真正会渲染的名字；关于页按它描述能力，不要按包名描述。 */
var HOST_KIT_COMPONENTS = [
  'Button', 'Switch', 'Modal', 'Input', 'Checkbox',
  'SegmentedControl', 'SegmentedTabs', 'Tag', 'StateDot',
  'Tooltip', 'Pill', 'Menu',
]

/** native = 全部可用；partial = 包在但缺件；fallback = 包不可用。 */
function hostKitState() {
  if (!hostUi) return { state: 'fallback', missing: HOST_KIT_COMPONENTS.slice() }
  var missing = HOST_KIT_COMPONENTS.filter(function (name) {
    return hostComponent(name) === null
  })
  return { state: missing.length === 0 ? 'native' : 'partial', missing: missing }
}
```

`HOST_KIT_COMPONENTS` 只列你**实际会渲染**的组件。不要把所有导出都列进去，否则「关于页」会声称支持未使用的控件。

## 2. 状态与展示

`hostKitState()` 返回三种状态：

| 状态 | 含义 | 界面策略 |
|---|---|---|
| `native` | 所有列出的组件都解析成功 | 正常使用宿主组件 |
| `partial` | 包存在但缺件 | 缺失的组件自动走 fallback；关于页提示 |
| `fallback` | 包不可用 | 全部走 fallback；关于页提示 |

关于页/测试页只描述 `HOST_KIT_COMPONENTS`，并且显示实际状态，不要写死「已接入官方组件」。

## 3. 图标

图标也是宿主原语包的一部分。用一个映射表把本地图标名映射到宿主图标组件，未命中的继续用本地 SVG：

```js
var HOST_ICON_MAP = {
  search: 'IconSearchOutlineRegular',
  settings: 'IconSettingsOutlineRegular',
  plus: 'IconPlusOutlineRegular',
  play: 'IconPlayOutlineRegular',
  close: 'IconCloseOutlineRegular',
  more: 'IconEllipsisOutlineRegular',
}

function icon(name, size) {
  var HostIcon = hostComponent(HOST_ICON_MAP[name] || '')
  if (HostIcon !== null) return h(HostIcon, { size: size })
  return localIcon(name, size)
}
```

图标尺寸用 12 / 14 / 16 / 18 四档；不要在业务里随手写 15、17 这类值。

## 4. 宿主不可用时

- 不要抛出异常；`hostUi = null` 后所有适配层自然走 fallback；
- 不要缓存「上次是 native」；每次渲染都通过 `hostComponent` 判断；
- 测试里可以显式把 `hostUi` 置空来跑 fallback 路径，但不要为此加全局开关。

## 5. 为什么不能直接在业务里 require

```text
业务直接 require      → 升级/降级要改 N 处；测试难以切换；缺失时抛错
唯一入口 + 适配层      → 升级只改一处；测试可切换；缺失自动降级
```
